Foundations · 00

What an array really is

Every trick in this notebook is a consequence of one physical fact: an array is a single block of memory with equally sized boxes. Understand the block, and half the answers become obvious.

An array is a contiguous collection of elements of the same type. "Contiguous" is the whole story — the elements sit next to each other in RAM with no gaps, so the computer never has to search for element i. It computes where it is:

address(arr[i]) = base_address + i × size_of_one_element arr = [10, 20, 30, 40] (int = 4 bytes, base = 1000) index : 0 1 2 3 addr : 1000 1004 1008 1012 value : 10 20 30 40 arr[2] → 1000 + 2×4 = 1008 → one multiplication and one addition → O(1)

That single formula explains the entire cost table below. Reading is instant because it is arithmetic. Inserting in the middle is slow because contiguity must be preserved — everything to the right physically shifts.

OperationTimeWhy
Access arr[i]O(1)Address arithmetic, no scanning
Update arr[i] = xO(1)Same — jump straight to the box
Search (unsorted)O(N)Could be anywhere; must look at each box
Search (sorted)O(log N)Binary search — see the companion notebook
Insert / delete at endO(1)*Nothing shifts (*amortised for dynamic arrays)
Insert / delete in middleO(N)All elements to the right shift by one
TraverseO(N)Touch every element once

Static vs dynamic arrays

A static array (int a[10]) has its size fixed at compile time and usually lives on the stack. A dynamic array (C++ vector, Java ArrayList, Python list) lives on the heap and grows. Growth is not free — when the buffer is full, the library allocates a bigger block (typically 2× in C++ / Java, ~1.125× in Python) and copies everything over.

Amortised O(1) — a favourite follow-up

Copying costs O(N), so how is push_back called O(1)? Because doubling makes the expensive copies rare. Inserting N elements triggers copies of size 1 + 2 + 4 + … + N ≈ 2N, so the total cost of N pushes is O(N), and the average per push is O(1). That average is what "amortised O(1)" means. Any single push can still be O(N).

2D arrays are 1D arrays in disguise

A matrix is stored flat, row after row (row-major order in C, C++, Python; column-major in Fortran and MATLAB). For an m × n matrix:

flat_index(mat[i][j]) = i × n + j (row-major) mat = [[1,2,3], [4,5,6]] m=2, n=3 memory : 1 2 3 4 5 6 index : 0 1 2 3 4 5 mat[1][2] → 1×3 + 2 = 5 → value 6 ✓

This is the trick behind "treat the 2D matrix as a 1D sorted array" in binary search problems, and behind the row/column swap in matrix rotation.

Cache locality — the answer that impresses

Looping for i: for j: mat[i][j] is dramatically faster than for j: for i: mat[i][j], even though both are O(m·n). Row-major storage means the first version walks memory in a straight line, so every cache line fetched is fully used. The second jumps by n elements each step and thrashes the cache. Same complexity, several times the wall-clock. Say this when an interviewer asks "can you make it faster without changing the complexity?"

Memory hook: subarray = "no jumping", subsequence = "jumping allowed, no going back", subset = "anything goes". Getting this wrong in the first 30 seconds of a problem is the most common way candidates solve the wrong question.

Interview Q&A on the fundamentals
Why is array indexing 0-based?

Because the index is really an offset from the base address. The first element sits at base + 0, so its offset is 0. 1-based indexing would need a subtraction on every access.

Array vs linked list — when do you choose each?

Array: you need O(1) random access, memory efficiency, or cache-friendly iteration. Linked list: you need O(1) insertion/deletion at a known position and the size varies wildly. In practice arrays win far more often than textbooks suggest because of cache behaviour.

Why can't an array hold mixed types in C++ but a Python list can?

Because address arithmetic needs a fixed element size. A Python list dodges this by storing pointers of equal size that point to objects elsewhere — which is also why Python lists are slower and use more memory than a C++ vector or a NumPy array.

What happens on out-of-bounds access?

In C++ with [] it is undefined behaviour — you read whatever bytes are there, silently. vector::at() throws std::out_of_range. Java throws ArrayIndexOutOfBoundsException, and Python raises IndexError (with negative indices wrapping around instead).

How do you pass an array to a function without copying it?

C++: pass by reference, void f(vector<int>& a) — note the &. Without it the whole vector is copied, turning an O(1) call into O(N). Adding const when you do not modify it is the professional touch. In Python and Java, lists/arrays are already passed by reference.

What is amortised time in one sentence?

The average cost per operation across a long sequence of operations, where occasional expensive steps are paid for by many cheap ones — as in vector doubling.

The ten patterns that cover all 40 problems

You are not learning 40 problems. You are learning 10 patterns and 40 costumes. When you recognise the pattern in the first minute, the code writes itself.

1 · Hashing

Trade memory for time. Store what you have seen in a map or set so a future lookup is O(1) instead of a rescan.

Trigger: "have I seen this before?", "count of", "pair that sums to"
2 · Two pointers

Two indices moving with a rule — from both ends inward, or both from the left at different speeds.

Trigger: sorted array, pair/triplet sums, in-place partitioning
3 · Sliding window

A moving subarray. Expand the right edge; shrink the left edge when a condition breaks. Each element enters and leaves once → O(N).

Trigger: "longest/shortest subarray such that…", all-positive arrays
4 · Prefix sum + hashmap

sum(i..j) = prefix[j] − prefix[i−1]. Store prefixes in a map to find subarrays with a target sum in one pass.

Trigger: subarray sum/xor with negatives allowed, counting subarrays
5 · Kadane / running DP

Carry one running value. At each element ask: extend the previous block, or start fresh here?

Trigger: maximum/minimum subarray sum or product
6 · Sorting first

Sorting costs O(N log N) but makes duplicates adjacent and enables two pointers. Often the cheapest path to "better".

Trigger: intervals, k-sum, "without extra space" constraints
7 · In-place swapping

Rearrange using swaps and reversals so extra space stays O(1). Reversal is the secret weapon for rotation.

Trigger: "do it in-place", "O(1) extra space", rotations, Dutch flag
8 · Index as hash

When values are bounded by 1..N, the array is its own hash table. Mark by negating or by cyclic placement.

Trigger: values in range 1..N, missing/repeating numbers
9 · Math & XOR tricks

Sum formulas, x ^ x = 0, and pairwise equations replace whole hash tables with O(1) space.

Trigger: "appears once", "one missing", exactly-one-anomaly problems
10 · Merge-sort counting

Piggyback on the merge step: while merging two sorted halves, count the cross-pairs you would otherwise find in O(N²).

Trigger: inversions, reverse pairs, "count pairs i<j with…"
Bonus · Matrix layer walk

Treat a matrix as concentric rings (spiral) or use transpose + reverse (rotation). Both are pure index bookkeeping.

Trigger: spiral order, rotate 90°, set matrix zeroes
Bonus · Moore's voting

Cancel out different elements pairwise; whatever survives is the only possible majority. Always verify with a second pass.

Trigger: "element appearing more than n/2 or n/3 times"

Constraints tell you the intended complexity

Before writing anything, look at N. Roughly 108 simple operations fit in one second, so the constraint names the algorithm:

"N is 105, so O(N²) is 1010 operations and will time out — I need at least O(N log N)." That one sentence tells the interviewer you think like an engineer, not a pattern-matcher, and it earns you the hint if you get stuck.

Foundations · 02

Brute → Better → Optimal: the ladder you must always climb

Striver's entire method is this ladder, and interviewers grade you on it. Jumping straight to the optimal solution and getting it slightly wrong scores worse than climbing all three rungs cleanly.

  1. Brute force. The definition of the problem, written as loops. Always exists, always correct. State its complexity out loud, then say "let me improve this."
  2. Better. Usually one idea: sort it, or hash it. Removes one nested loop and gets you to O(N log N) or O(N) with extra space.
  3. Optimal. Usually a pattern: two pointers, prefix sums, Kadane, or an in-place trick that also kills the extra space.

Consider "find a pair that sums to a target" as the canonical example of the whole ladder:

RungIdeaTimeSpace
BruteCheck every pair with two loopsO(N²)O(1)
BetterHash map: look for target − arr[i]O(N)O(N)
OptimalSort, then two pointers from both endsO(N log N)O(1)
The trap

Notice that "optimal" is not always the fastest in time — here the hash map is O(N) while two pointers is O(N log N). Optimal means the best trade-off for the constraints you were given. If the interviewer says "O(1) space", the sorted two-pointer version wins. If they say "return the original indices", the hash map wins because sorting destroys indices. Ask which they care about; that question alone is worth marks.

The bugs that fail array interviews

Almost nobody fails these problems because they did not know the idea. They fail on eight recurring mistakes.

#BugFix
1Initialising maxi = 0 when the array can be all negativeInitialise with arr[0] or INT_MIN / float('-inf')
2Integer overflow on sums and products (N=10⁵ × values 10⁹)Use long long in C++; Python integers are unbounded
3Off-by-one in loop bounds — i <= n, or arr[i+1] at the last indexLoop to n-1 when you look ahead; dry run the last iteration
4Forgetting duplicates in 3-sum / 4-sum / unionSkip equal neighbours after sorting: while(i<n-1 && a[i]==a[i+1]) i++;
5Modifying a container while iterating over itCollect indices first, mutate afterwards; or iterate backwards
6Sliding window on an array containing negativesWindows need monotonic growth — with negatives, switch to prefix sum + hashmap

8Claiming unordered_map is O(1) without qualificationWorst case is O(N) from hash collisions; say "O(1) average" and mention map is O(log N) guaranteed
The unordered_map warning that surprises candidates

In competitive settings, unordered_map can be attacked with anti-hash test cases that force every key into one bucket, degrading O(N) work to O(N²). If an interviewer asks "what is the worst case of your hash solution?", the correct answer is O(N²) in theory, O(N) in practice, and the guaranteed fix is std::map at O(N log N) or a custom hash with a random seed.

Three test cases to state unprompted, every single time

1. Normal case. 2. Smallest input — empty array and single element. 3. All same / all negative / already sorted. Volunteering these before the interviewer asks converts "wrote code" into "engineers software".

A1

Largest Element in an Array

GFGTraversalO(N)Foundational

Given an array, return the largest element in it.

Input : arr = [2, 5, 1, 3, 0] Output: 5 Input : arr = [8, 10, 5, 7, 9] Output: 10

Brute force — sort it

  1. Sort the array in ascending order.
  2. Return the last element, arr[n-1].
Time O(N log N)Space O(1)

Optimal — one pass

  1. Set maxi = arr[0]. Never start at 0 — the array may be all negative.
  2. Traverse from index 1 to n−1.
  3. If arr[i] > maxi, update maxi = arr[i].
  4. Return maxi.
largest element
int largestElement(vector<int>& arr) {
    int maxi = arr[0];                 // NOT 0 - array may be all negative
    for (int i = 1; i < arr.size(); i++) {
        if (arr[i] > maxi) maxi = arr[i];
    }
    return maxi;
}
// One-liner: *max_element(arr.begin(), arr.end());
def largest_element(arr):
    maxi = arr[0]                      # NOT 0 - array may be all negative
    for i in range(1, len(arr)):
        if arr[i] > maxi:
            maxi = arr[i]
    return maxi

# One-liner: max(arr)
Time O(N)Space O(1)
The classic mistake

int maxi = 0; returns 0 for [-5, -2, -9] — a number that is not even in the array. Interviewers plant negative arrays specifically to catch this.

Interview Q&A
Why is one pass better than sorting if both "work"?

Sorting does far more work than the question needs — it orders all N elements when you only asked about one. O(N) vs O(N log N), and sorting also destroys the original order, which may matter to the caller.

What is the minimum number of comparisons to find the maximum?

Exactly N−1. Think of it as a knockout tournament: every element except the winner must lose exactly one comparison, so N−1 comparisons are both necessary and sufficient.

Find the maximum AND minimum together — can you beat 2N comparisons?

Yes. Process elements in pairs: compare the two against each other first (1 comparison), then the smaller against min and the larger against max (2 more). That is 3 comparisons per 2 elements = 3N/2 instead of 2N.

What if the array is empty?

arr[0] is undefined behaviour. Guard with if (arr.empty()) throw / return INT_MIN and — more importantly — ask the interviewer what the expected behaviour is. Asking scores better than guessing.

A2

Second Largest Element Without Sorting

GFGTraversalO(N)Edge cases

Find the second largest element. If it does not exist (all elements equal, or fewer than two distinct values), return −1. Distinct is the key word: in [1, 2, 4, 4, 5] the answer is 4, but in [5, 5, 5] it is −1.

Input : arr = [1, 2, 4, 7, 7, 5] Output: 5 (7 is largest, 5 is the second DISTINCT largest) Input : arr = [2, 2, 2] Output: -1 (no second distinct element)

Brute force

  1. Sort the array ascending.
  2. Walk backwards from n-2 until you find an element different from arr[n-1].
  3. Return it, or −1 if the walk finishes.
Time O(N log N)Space O(1)

Better — two passes

First pass finds the largest. Second pass finds the biggest element strictly smaller than that. Correct, but O(2N) and needs two loops.

Optimal — single pass, two variables

  1. Set largest = arr[0] and second = INT_MIN.
  2. For each element from index 1: if arr[i] > largest, the old largest becomes second (second = largest; largest = arr[i];).
  3. Else if arr[i] < largest AND arr[i] > second, update second = arr[i]. The strict < largest is what skips duplicates.
  4. Return second == INT_MIN ? -1 : second.
second largest — one pass
int secondLargest(vector<int>& arr) {
    int n = arr.size();
    if (n < 2) return -1;
    int largest = arr[0], second = INT_MIN;
    for (int i = 1; i < n; i++) {
        if (arr[i] > largest) {
            second  = largest;         // demote the old champion
            largest = arr[i];
        } else if (arr[i] < largest && arr[i] > second) {
            second  = arr[i];          // strict < skips duplicates of largest
        }
    }
    return second == INT_MIN ? -1 : second;
}
def second_largest(arr):
    n = len(arr)
    if n < 2:
        return -1
    largest, second = arr[0], float('-inf')
    for i in range(1, n):
        if arr[i] > largest:
            second, largest = largest, arr[i]      # demote old champion
        elif largest > arr[i] > second:            # strict < skips duplicates
            second = arr[i]
    return -1 if second == float('-inf') else second
Time O(N)Space O(1)
Mirror problem — second smallest

Identical logic with the comparisons flipped: smallest = arr[0], second = INT_MAX; if arr[i] < smallest demote, else if arr[i] > smallest && arr[i] < second update. Interviewers often ask for both in one pass — just track four variables.

Interview Q&A
Why not simply sort and take arr[n-2]?

Duplicates break it: [1, 5, 5] sorted gives arr[n-2] = 5, but 5 is the largest, not the second. You must skip equal values — and once you handle that, the O(N) version is simpler anyway.

Extend this to the K-th largest element.

For small K, keep K variables — but that gets ugly fast. The standard answers are: a min-heap of size K in O(N log K), or Quickselect in O(N) average / O(N²) worst. Mentioning Quickselect and its pivot-based partition is the strong answer.

Why INT_MIN as the sentinel and not −1?

Because −1 could be a legitimate array value. INT_MIN as a sentinel is only safe if the array cannot contain it — if it can, use a boolean found flag instead. That nuance is exactly the kind of thing a senior interviewer probes.

A3

Check if the Array is Sorted

LC 1752TraversalO(N)

Return true if the array is sorted in non-decreasing order. The follow-up variant — sorted and rotated — is the one that actually shows up in interviews.

arr = [1, 2, 3, 4, 5] → true arr = [1, 3, 2, 4] → false arr = [3, 4, 5, 1, 2] → false (sorted) but TRUE (sorted & rotated)

Optimal — adjacent comparison

  1. Loop i from 1 to n−1.
  2. If arr[i-1] > arr[i], order is broken → return false immediately.
  3. If the loop completes, return true.

Note the arr[i-1] form — comparing backwards means the index never runs past the end. Writing arr[i] > arr[i+1] with i < n is the #1 off-by-one crash here.

The real interview version — sorted AND rotated

Insight: a sorted-and-rotated array has at most one "drop" point where arr[i] > arr[i+1], treating the array as circular. Zero drops means plain sorted; one drop means rotated; two or more means neither.

sorted & sorted-rotated
bool isSorted(vector<int>& arr) {
    for (int i = 1; i < arr.size(); i++)
        if (arr[i - 1] > arr[i]) return false;
    return true;
}

// LC 1752 - check if sorted AND rotated
bool checkSortedRotated(vector<int>& arr) {
    int n = arr.size(), drops = 0;
    for (int i = 0; i < n; i++)
        if (arr[i] > arr[(i + 1) % n]) drops++;   // %n makes it circular
    return drops <= 1;
}
def is_sorted(arr):
    for i in range(1, len(arr)):
        if arr[i - 1] > arr[i]:
            return False
    return True

# LC 1752 - check if sorted AND rotated
def check_sorted_rotated(arr):
    n = len(arr)
    drops = sum(1 for i in range(n) if arr[i] > arr[(i + 1) % n])
    return drops <= 1                              # %n makes it circular
Time O(N)Space O(1)
Remember this

Sorted = 0 drops. Sorted and rotated = at most 1 drop (circular). The modulo (i+1) % n is what wraps the last element around to the first — that comparison is the one everyone forgets.

Interview Q&A
Can you check sortedness in less than O(N)?

No. Any element you did not look at could be the one that breaks the order, so every element must be examined at least once — a formal adversary argument giving an Ω(N) lower bound.

Why does the drop count work?

A sorted array increases everywhere. Rotating it cuts the sequence at one point and swaps the two pieces, creating exactly one place where a bigger number is followed by a smaller one. More than one such place means the data was never a rotation of a sorted list.

How do duplicates affect it?

Use non-strict comparison (>, not >=) so that equal neighbours are not counted as drops. [2, 2, 2] has 0 drops and is correctly reported as sorted.

A4

Remove Duplicates from Sorted Array

LC 26Two pointersO(N)In-place

Given a sorted array, remove duplicates in-place so each unique element appears once, and return the count of unique elements. What lies beyond that count does not matter.

Input : arr = [1, 1, 2, 2, 2, 3, 3] Output: 3, arr = [1, 2, 3, _, _, _, _] Two-pointer trace: i=0 j scans → [1] 1 2 2 2 3 3 j=1: arr[1]==arr[i] → skip ↑i ↑j [1, 2] 2 2 3 3 j=2: arr[2]!=arr[i] → i++, arr[i]=2 ↑i ↑j [1, 2, 3] 2 3 j=5: arr[5]!=arr[i] → i++, arr[i]=3 ↑i ↑j answer = i + 1 = 3

Brute force — use a set

  1. Insert every element into an ordered set, which discards duplicates and keeps order.
  2. Copy the set back into the front of the array.
  3. Return the set's size.
Time O(N log N)Space O(N)

Optimal — two pointers

Insight: because the array is sorted, duplicates are always adjacent. Pointer i marks the last position of the clean region; pointer j scans ahead looking for a new value.

  1. Set i = 0 (last index of the unique region).
  2. Run j from 1 to n−1.
  3. If arr[j] != arr[i], we found a new value: do i++ then arr[i] = arr[j].
  4. Otherwise it is a duplicate — do nothing, just let j move on.
  5. Return i + 1, the count of unique elements.
remove duplicates in-place
int removeDuplicates(vector<int>& arr) {
    int n = arr.size();
    if (n == 0) return 0;
    int i = 0;                          // last index of the unique region
    for (int j = 1; j < n; j++) {
        if (arr[j] != arr[i]) {         // a brand new value
            i++;
            arr[i] = arr[j];
        }
    }
    return i + 1;                       // count = index + 1
}
def remove_duplicates(arr):
    n = len(arr)
    if n == 0:
        return 0
    i = 0                               # last index of the unique region
    for j in range(1, n):
        if arr[j] != arr[i]:            # a brand new value
            i += 1
            arr[i] = arr[j]
    return i + 1                        # count = index + 1
Time O(N)Space O(1)
Follow-up: allow each element at most twice (LC 80)

Start i = 2 and j = 2, and copy when arr[j] != arr[i-2]. The generalisation to "at most K times" is arr[j] != arr[i-K] — a very common follow-up, and it looks impressive because it is one character different.

Interview Q&A
Why does this need the array to be sorted?

Because sortedness guarantees duplicates are adjacent, so comparing against the single previous unique element is enough. On unsorted data you would have to remember every value seen — that is a hash set, O(N) extra space.

What is actually left in the tail of the array?

Whatever was there before — garbage from the caller's perspective. LeetCode explicitly ignores it. Mentioning that you are not clearing it, and that the caller must trust the returned length, shows you understand the contract.

Two pointers here — same technique as elsewhere?

This is the slow/fast (read/write) pointer flavour: both start at the left, the fast one reads and the slow one writes. The other flavour is opposite ends converging, used in 2-sum on sorted arrays and in reversal. Naming the flavour you are using is a nice touch.

A5

Left Rotate an Array by One Place

GFGIn-placeO(N)

Shift every element one position to the left; the first element wraps around to the end.

Input : arr = [1, 2, 3, 4, 5] Output: [2, 3, 4, 5, 1]

Optimal

  1. Save the first element: temp = arr[0]. Losing it is the only real risk.
  2. For i from 1 to n−1, copy leftwards: arr[i-1] = arr[i].
  3. Put the saved value at the end: arr[n-1] = temp.
left rotate by one
void rotateByOne(vector<int>& arr) {
    int n = arr.size();
    if (n <= 1) return;
    int temp = arr[0];                  // save it BEFORE overwriting
    for (int i = 1; i < n; i++) arr[i - 1] = arr[i];
    arr[n - 1] = temp;
}
def rotate_by_one(arr):
    n = len(arr)
    if n <= 1:
        return
    temp = arr[0]                       # save it BEFORE overwriting
    for i in range(1, n):
        arr[i - 1] = arr[i]
    arr[n - 1] = temp
Time O(N)Space O(1)
Interview Q&A
Right rotate by one — what changes?

Save arr[n-1], then loop backwards from n-1 down to 1 doing arr[i] = arr[i-1], and finish with arr[0] = temp. Direction of the loop must be opposite to the direction of the shift, or you overwrite data you still need.

Can rotation be done in O(1) time?

Not if the data must physically move. But if you control the access layer, you can keep an offset and read arr[(i + offset) % n] — rotation becomes O(1) by never moving anything. This is how circular buffers and deques work, and it is a great answer.

A6

Left Rotate an Array by D Places

LC 189Reversal trickO(N) / O(1)Must know

Rotate the array left by d positions, in-place, using O(1) extra space. This is one of the most asked easy problems in placements.

Input : arr = [1,2,3,4,5,6,7], d = 2 Output: [3,4,5,6,7,1,2] REVERSAL ALGORITHM (3 reversals): original : 1 2 3 4 5 6 7 reverse first d : 2 1 | 3 4 5 6 7 reverse rest : 2 1 | 7 6 5 4 3 reverse whole : 3 4 5 6 7 1 2 ✓

Brute force — temp array

  1. Copy the first d elements into a temporary array.
  2. Shift the remaining n-d elements left by d positions.
  3. Copy the temp array back into the last d slots.
Time O(N)Space O(d)

Optimal — the reversal algorithm

First, always do d = d % n. Rotating a 5-element array by 7 is the same as rotating it by 2, and skipping this line is the single most common bug (it crashes when d > n).

  1. d = d % n — normalise the rotation amount.
  2. Reverse the block [0, d-1].
  3. Reverse the block [d, n-1].
  4. Reverse the entire array [0, n-1].

Why it works: writing the array as two blocks A and B, you want BA from AB. Reversing each block gives ArBr, and reversing that whole thing gives (ArBr)r = BA. Three reversals touch each element at most twice → O(N) time, O(1) space.

Interview Q&A
What happens if you forget d = d % n?

For d > n the first reverse gets a range beyond the array — out-of-bounds access or a crash. Even for d == n you do unnecessary work. This one line is the most commonly missed part of the problem.

What is the juggling algorithm?

An alternative that moves each element directly to its final position by walking cycles of length n / gcd(n, d), starting gcd(n, d) separate cycles. Same O(N)/O(1) bounds, but harder to write and to explain — mention you know it, then write the reversal version.

Why is the reversal method preferred in interviews?

It is four lines, has no modular-arithmetic cycle bookkeeping, is trivially provable via (ArBr)r = BA, and reuses a helper you will need in several other problems (next permutation, rotate matrix).

Rotate a linked list by k — same idea?

No — reversal is expensive on a singly linked list. Instead, connect the tail to the head to form a circle, walk to the new tail at position n − k % n, and break the circle there. O(N) time, O(1) space.

Union of Two Sorted Arrays

GFGTwo pointersO(N+M)Merge step

Given two sorted arrays, return their union — every distinct element from both, in sorted order.

Input : a = [1, 2, 3, 4, 5], b = [2, 3, 4, 4, 5] Output: [1, 2, 3, 4, 5] Input : a = [1, 1, 2], b = [2, 3] Output: [1, 2, 3]

Brute force — a set

Insert everything from both arrays into a set, then copy it out. Correct and two lines long, but O((N+M) log(N+M)) time and O(N+M) space — and it wastes the fact that the inputs are already sorted.

Optimal — two pointers (the merge step)

  1. Set i = 0, j = 0.
  2. While both pointers are in range: take the smaller of a[i] and b[j]; if they are equal take one and advance both.
  3. Before pushing a value, check it is not equal to the last value already in the result — that filters duplicates.
  4. When one array is exhausted, drain the other with the same duplicate check.
union of sorted arrays
vector<int> unionSorted(vector<int>& a, vector<int>& b) {
    int n = a.size(), m = b.size(), i = 0, j = 0;
    vector<int> res;

    auto push = [&](int v) {                    // add only if not a repeat
        if (res.empty() || res.back() != v) res.push_back(v);
    };

    while (i < n && j < m) {
        if (a[i] < b[j])       push(a[i++]);
        else if (a[i] > b[j])  push(b[j++]);
        else { push(a[i]); i++; j++; }          // equal - take one, skip both
    }
    while (i < n) push(a[i++]);                 // drain leftovers
    while (j < m) push(b[j++]);
    return res;
}

Interview Q&A
Why not just use a set if it is shorter?

Because it throws away the sorted property you were handed, adding a log factor for no reason. The point of the problem is recognising that "two sorted arrays" means "run the merge step of merge sort".

What if the inputs are NOT sorted?

Then a hash set is genuinely optimal at O(N+M) average, versus sorting first at O(N log N + M log M). The right algorithm depends on the input guarantee — never answer before you have confirmed it.

How do you handle duplicates within one array, like [1,1,2]?

The res.back() != v check handles both intra-array and cross-array duplicates in one rule, which is why it is better than special-casing the equality branch.

Brute force

For every element of a, scan b for a match and mark that position of b as used (with a visited array) so it is not matched twice. O(N×M) time, O(M) space.

  5. Stop when either pointer runs out.

    }
    return res;
}

They are the same loop. Union pushes on every branch (with a duplicate guard); intersection pushes only on the equal branch. Remember one, derive the other.

Find the Missing Number

LC 268Math / XORO(N)O(1) space

An array of size N contains N distinct numbers taken from the range 1..N+1 (or 0..N — read the statement carefully). Exactly one number is missing. Find it.

Input : arr = [1, 2, 4, 5], N = 5 Output: 3 Sum approach : expected = 5×6/2 = 15, actual = 12 → 15 − 12 = 3 XOR approach : (1^2^3^4^5) ^ (1^2^4^5) = 3

Brute force

For each candidate 1..N, scan the array looking for it. First one not found is the answer. O(N²).

Better — hashing

Build a boolean array of size N+1, mark each present number, then scan for the unmarked index. O(N) time but O(N) extra space.

Optimal 1 — sum formula

  1. Expected sum of 1..N is N × (N + 1) / 2.
  2. Compute the actual sum of the array in one pass.
  3. The missing number is expected − actual.

Optimal 2 — XOR (overflow-proof)

Key facts: x ^ x = 0 and x ^ 0 = x. XOR everything from 1..N, then XOR every array element. Every present number appears twice and cancels itself out; the missing one survives alone.

missing number — both ways
// Method 1: sum formula  (use long long - N=10^5 sums overflow int fast)
int missingSum(vector<int>& arr, int N) {
    long long expected = 1LL * N * (N + 1) / 2;
    long long actual = 0;
    for (int x : arr) actual += x;
    return (int)(expected - actual);
}

// Method 2: XOR  (no overflow, ever)
int missingXor(vector<int>& arr, int N) {
    int x1 = 0, x2 = 0;
    for (int i = 1; i <= N; i++) x1 ^= i;      // XOR of the full range
    for (int v : arr)            x2 ^= v;      // XOR of what we have
    return x1 ^ x2;                            // pairs cancel, missing survives
}

    return N * (N + 1) // 2 - sum(arr)

Why interviewers prefer the XOR answer

The sum method can overflow: for N = 105 the sum is about 5×109, which does not fit in a 32-bit int. XOR never grows beyond the largest input value, so it cannot overflow. Give both, then say "I would ship the XOR version because it is overflow-safe."

Interview Q&A
Two numbers are missing instead of one — now what?

Sum gives a + b and sum-of-squares gives a² + b²; two equations, two unknowns. The XOR route is more elegant: XOR everything to get a ^ b, isolate any set bit of it, and partition all numbers into two groups by that bit — each group XORs down to one missing number. This is exactly problem C9's machinery.

Why does x ^ x = 0 make this work?

XOR is associative and commutative, so the order of operations does not matter. Every number that is present appears once from the range and once from the array, so it pairs up and vanishes. Only the unpaired one is left.

The range is 0..N instead of 1..N — what changes?

The expected sum becomes N(N+1)/2 over 0..N (0 adds nothing, so the formula is unchanged), and the XOR loop runs from 0 to N. Always restate the range aloud before coding — LC 268 uses 0..N while most GFG versions use 1..N.

Every element appears three times except one (LC 137). Does XOR still work?

No — XOR only cancels in pairs, and three copies leave one behind. The standard fix is bit counting: for each of the 32 bit positions, count how many numbers have that bit set; every count that is not divisible by 3 belongs to the loner. O(32N) = O(N) time, O(1) space.

A14

Longest Subarray with Sum K

GFG / LC 325Sliding windowPrefix + hashmapO(N)Two variants!

Find the length of the longest contiguous subarray whose sum equals K. There are two versions of this problem and they need different algorithms — this is the single most important distinction in the easy set.

Variant 1 — only positives (and zeros): arr = [2,3,5,1,9], k = 10 → 3 ([2,3,5]) Variant 2 — positives AND negatives : arr = [-1,1,1,1,2,3], k = 3 → 5 ([1,1,1,2,-1... ]) Why the difference? Sliding window works ONLY when growing the window can never DECREASE the sum. A negative number breaks that guarantee, so the window logic becomes invalid.

Brute force (works for both variants)

  1. For each start index i, run j from i to n−1 accumulating a running sum.
  2. Whenever the running sum equals K, update the answer with j - i + 1.
Time O(N²)Space O(1)

Optimal for positives — sliding window

  1. left = 0, right = 0, sum = 0.
  2. Expand: add arr[right] to the sum.
  3. While sum > k, shrink from the left: subtract arr[left], then left++.
  4. If sum == k, update maxLen = max(maxLen, right - left + 1).
  5. Move right forward and repeat. Each index enters and exits once → O(N).

Optimal for positives + negatives — prefix sum + hashmap

Insight: if prefix[j] − prefix[i] = k, then the subarray from i+1 to j sums to k. So at each index, look for the prefix value sum − k in a map. Store the earliest index for each prefix sum, because earlier start means longer subarray.

// VARIANT 1 - positives only: sliding window, O(N) time, O(1) space
int longestSubarrayPositive(vector<int>& arr, long long k) {
    int n = arr.size(), left = 0, maxLen = 0;
    long long sum = 0;
    for (int right = 0; right < n; right++) {
        sum += arr[right];                       // expand
        while (sum > k && left <= right) {       // shrink while too big
            sum -= arr[left];
            left++;
        }
        if (sum == k) maxLen = max(maxLen, right - left + 1);
    }
    return maxLen;
}

The line that decides the problem

Decision rule to memorise

Interview Q&A
Why exactly does the sliding window fail with negatives?

The window relies on monotonicity: extending right only increases the sum, so "sum too big → shrink" is a valid rule. With a negative element, extending right can decrease the sum, so shrinking may throw away a start index that would have worked later. The invariant is gone, and so is correctness.

Why does sum == k need its own check in the map version?

Because a subarray starting at index 0 has no preceding prefix to subtract. The alternative is to seed the map with {0: -1} — a "virtual empty prefix" — which handles it uniformly and is the cleaner idiom.

What is the worst-case time of the hashmap version?

O(N) average, but O(N²) worst case if the hash function collides badly. Use map for a guaranteed O(N log N), and say so — the interviewer is checking whether you treat hashing as magic.

Each element enters and leaves the window once — so why does the nested while loop not make it O(N²)?

Because left only ever moves forward and never resets. Across the whole run it advances at most N times total, so the inner loop's total work is O(N), not O(N) per iteration. This amortised argument is exactly what interviewers want to hear about sliding windows.

Find two elements that add up to target. Two flavours: return the indices, or just return true/false. That difference decides which algorithm is correct.

Input : arr = [2, 6, 5, 8, 11], target = 14 Output: [1, 3] (6 + 8 = 14) Hashmap trace (looking for target - arr[i]): i=0 arr=2 need 12 not in map → store {2:0} i=1 arr=6 need 8 not in map → store {6:1} i=2 arr=5 need 9 not in map → store {5:2} i=3 arr=8 need 6 FOUND at 1 → answer [1, 3] ✓

Brute force

Two nested loops over every pair (i, j) with j > i. O(N²) time, O(1) space.

Optimal for indices — hashmap, one pass

  1. Create an empty map from value → index.
  2. For each i, compute need = target − arr[i].
  3. If need is already in the map, return {map[need], i}.
  4. Otherwise store map[arr[i]] = i and continue.

Storing after checking is what prevents an element from pairing with itself.

Optimal for yes/no with O(1) space — sort + two pointers

  1. Sort the array.
  2. left = 0, right = n − 1.
  3. If arr[left] + arr[right] == target → found.
  4. If the sum is too small, left++ (only way to increase it). If too big, right--.
  5. Stop when the pointers cross.
2 sum — both approaches
// Returns INDICES - hashmap, O(N) time, O(N) space
vector<int> twoSum(vector<int>& arr, int target) {
    unordered_map<int, int> seen;              // value -> index
    for (int i = 0; i < arr.size(); i++) {
        int need = target - arr[i];
        if (seen.count(need)) return {seen[need], i};
        seen[arr[i]] = i;                      // store AFTER checking
    }
    return {-1, -1};
}

// Returns YES/NO - sort + two pointers, O(N log N) time, O(1) space
bool twoSumExists(vector<int> arr, int target) {
    sort(arr.begin(), arr.end());              // NOTE: destroys indices
    int l = 0, r = arr.size() - 1;
    while (l < r) {
        int sum = arr[l] + arr[r];
        if      (sum == target) return true;
        else if (sum < target)  l++;           // need a bigger number
        else                    r--;           // need a smaller number
    }
    return false;
}

The trap that fails candidates

If the problem asks for indices, you cannot sort — sorting scrambles them. Candidates who reflexively answer "sort and two pointers" for LC 1 get it wrong. Ask: "indices or just existence?"

Interview Q&A
Why check the map before inserting?

Otherwise arr[i] could match itself when target = 2 × arr[i], returning the same index twice. Check-then-insert makes it impossible.

What if multiple valid pairs exist?

The hashmap version returns the pair whose second element is earliest. If all pairs are required, do not return early — keep scanning and collect, but then you also need duplicate handling as in 3-sum.

The array is already sorted. Which do you pick?

Two pointers — O(N) time and O(1) space, beating the hashmap on memory with no sorting cost. That is LC 167.

How does this scale to 3-sum and 4-sum?

Fix the outer elements and run 2-sum inside: 3-sum is one loop + two pointers = O(N²); 4-sum is two loops + two pointers = O(N³). k-sum is a recursion that bottoms out at 2-sum.

Sort an Array of 0s, 1s and 2s

LC 75Dutch National FlagO(N) one passMust know

Sort an array containing only 0, 1 and 2 — in a single pass with O(1) space. Named after the Dutch flag's three stripes; the algorithm is Dijkstra's.

Input : arr = [2, 0, 2, 1, 1, 0] Output: [0, 0, 1, 1, 2, 2] INVARIANT — the array is always in four zones: [0 .. low-1] all 0s (settled) [low .. mid-1] all 1s (settled) [mid .. high] UNKNOWN (shrinking) [high+1 .. n-1] all 2s (settled)

Brute force

Just sort it — O(N log N). Correct but throws away the fact that there are only three distinct values.

Better — counting sort, two passes

Count the 0s, 1s and 2s in one pass, then overwrite the array with that many of each. O(2N) time, O(1) space. Perfectly acceptable — but the interviewer will then ask for one pass.

Optimal — Dutch National Flag, one pass

  1. low = 0, mid = 0, high = n − 1.
  2. While mid <= high, look at arr[mid]:
  3. 0 → swap arr[low] and arr[mid], then low++, mid++.
  4. 1 → it is already in the right zone, just mid++.
  5. 2 → swap arr[mid] and arr[high], then high-- and do not move mid.
Dutch National Flag
void sortColors(vector<int>& arr) {
    int low = 0, mid = 0, high = arr.size() - 1;
    while (mid <= high) {                      // note: <= not <
        if (arr[mid] == 0) {
            swap(arr[low], arr[mid]);
            low++; mid++;                      // swapped value is a known 1 or 0
        } else if (arr[mid] == 1) {
            mid++;                             // already in the right zone
        } else {                               // arr[mid] == 2
            swap(arr[mid], arr[high]);
            high--;                            // DO NOT move mid - value unseen
        }
    }
}
def sort_colors(arr):
    low, mid, high = 0, 0, len(arr) - 1
    while mid <= high:                         # note: <= not <
        if arr[mid] == 0:
            arr[low], arr[mid] = arr[mid], arr[low]
            low += 1
            mid += 1                           # swapped value is a known 1 or 0
        elif arr[mid] == 1:
            mid += 1                           # already in the right zone
        else:                                  # arr[mid] == 2
            arr[mid], arr[high] = arr[high], arr[mid]
            high -= 1                          # DO NOT move mid - value unseen

The two details that decide correctness

1. When you swap with high, do not advance mid — the value that just arrived from the right end has never been examined. Advancing skips it and breaks the algorithm.
2. The loop condition is mid <= high, not <. With < the final element is never processed.

Interview Q&A
Why is it safe to advance mid after swapping with low?

Because everything before mid has already been classified. The element at low can only be a 1 (or low == mid, meaning it is the same element). Either way the incoming value needs no further inspection.

What is the maximum number of swaps?

At most N — each swap either grows the settled 0-zone or shrinks the unknown region by one, and neither can happen more than N times.

Generalise to four distinct values.

Dutch flag does not extend cleanly beyond three. For K distinct values use counting sort in O(N + K), or a full sort if K is large. Saying "this trick is specifically three-way partitioning" shows you understand its limits.

Where else does three-way partitioning appear?

In quicksort with many duplicate keys — three-way partitioning around the pivot turns a degenerate O(N²) case into O(N log N). Same code, different context.

Majority Element (> N/2 times)

LC 169Moore's VotingO(N) / O(1)Must know

Find the element that appears more than ⌊N/2⌋ times. You may assume it exists (otherwise a verification pass is required).

Input : arr = [2, 2, 1, 1, 1, 2, 2] Output: 2 (appears 4 times out of 7, and 4 > 3) MOORE'S VOTING — cancellation trace: el=2 cnt=1 | 2 → cnt=2 | 1 → cnt=1 | 1 → cnt=0 cnt hit 0 → adopt next element: el=1 cnt=1 2 → cnt=0 | cnt hit 0 → el=2 cnt=1 survivor = 2 ✓

Brute force

For each element, count its occurrences with an inner loop. O(N²), O(1) space.

Better — hashmap

Count frequencies in a map and return the key with count > n/2. O(N) time, O(N) space. A completely acceptable answer if you then say "but I can do it in O(1) space."

Optimal — Boyer–Moore Voting Algorithm

Intuition: imagine every element as a voter. Two voters supporting different candidates cancel each other out. If one candidate has strictly more than half the votes, it cannot be fully cancelled — some of its votes must survive.

  1. count = 0, element = anything.
  2. For each value v: if count == 0, adopt it (element = v, count = 1).
  3. Else if v == element, count++ (a supporter).
  4. Else count-- (an opponent cancels one supporter).
  5. At the end, element is the only possible majority. Verify it with a second pass unless existence is guaranteed.
Moore's voting
int majorityElement(vector<int>& arr) {
    int count = 0, element = 0;
    for (int v : arr) {                        // PASS 1 - find the candidate
        if (count == 0) { element = v; count = 1; }
        else if (v == element) count++;        // a supporter
        else count--;                          // an opponent cancels one vote
    }
    // PASS 2 - verify (skip only if existence is guaranteed)
    int freq = 0;
    for (int v : arr) if (v == element) freq++;
    return freq > arr.size() / 2 ? element : -1;
}
def majority_element(arr):
    count, element = 0, None
    for v in arr:                              # PASS 1 - find the candidate
        if count == 0:
            element, count = v, 1
        elif v == element:
            count += 1                         # a supporter
        else:
            count -= 1                         # an opponent cancels one vote
    # PASS 2 - verify (skip only if existence is guaranteed)
    return element if arr.count(element) > len(arr) // 2 else -1
Time O(N)Space O(1)
Why the verification pass matters

Moore's algorithm always returns something. On [1, 2, 3] it returns 3, which is not a majority at all. The guarantee is one-directional: if a majority exists, the survivor is it — never the reverse. Interviewers ask this specifically to see whether you understand the algorithm or just memorised it.

Interview Q&A
Prove the algorithm is correct.

Each decrement pairs off one majority vote with one non-majority vote. There are fewer than N/2 non-majority elements, so at most that many majority votes can be cancelled. Since the majority has more than N/2 votes, at least one survives, and the counter can only be positive for the surviving candidate at the end.

What if there is no majority element?

The survivor is meaningless — hence the verification pass. Without it your function returns a confidently wrong answer, which is worse than returning nothing.

Can you solve it by sorting?

Yes — sort and return arr[n/2]. Any element occupying more than half the positions must cover the middle index. O(N log N), but it is a nice one-liner to mention as the "better" rung.

Extend to elements appearing more than n/3 times.

Track two candidates and two counters — at most two elements can exceed n/3. That is problem C2 in this notebook, and the pattern generalises: more than n/k times allows at most k−1 answers, needing k−1 counters.

Kadane's Algorithm — Maximum Subarray Sum

LC 53Kadane / DPO(N) / O(1)Most asked array algorithm

Find the maximum sum of any contiguous subarray. Clarify up front whether the empty subarray (sum 0) is allowed — it changes the answer for an all-negative array.

Input : arr = [-2, 1, -3, 4, -1, 2, 1, -5, 4] Output: 6 (subarray [4, -1, 2, 1]) Trace (sum = running, maxi = best ever): v=-2 : sum=-2 → negative, RESET sum=0 maxi=-2 v= 1 : sum= 1 maxi= 1 v=-3 : sum=-2 → RESET sum=0 maxi= 1 v= 4 : sum= 4 maxi= 4 v=-1 : sum= 3 maxi= 4 v= 2 : sum= 5 maxi= 5 v= 1 : sum= 6 maxi= 6 ★ v=-5 : sum= 1 maxi= 6 v= 4 : sum= 5 maxi= 6 ✓

Brute force / better

All pairs (i, j) with an inner sum → O(N³). Keeping a running sum in the inner loop → O(N²). Both are worth mentioning in one sentence before you jump to Kadane.

Optimal — Kadane's algorithm

The one-sentence idea: a running sum that has gone negative is a liability — dragging it into the next subarray can only make things worse — so throw it away and start fresh.

  1. sum = 0, maxi = INT_MIN (not 0 — that breaks all-negative arrays).
  2. For each element: sum += arr[i].
  3. maxi = max(maxi, sum) — record before any reset.
  4. If sum < 0, set sum = 0. This reset is the entire algorithm.
  5. Return maxi.
Kadane's algorithm
long long maxSubarraySum(vector<int>& arr) {
    long long sum = 0, maxi = LLONG_MIN;       // NOT 0 - handles all-negative
    for (int v : arr) {
        sum += v;
        maxi = max(maxi, sum);                 // record BEFORE resetting
        if (sum < 0) sum = 0;                  // negative prefix is a liability
    }
    return maxi;
}

The all-negative trap

For [-3, -1, -2]: if empty subarrays are not allowed, the answer is −1. If they are allowed, it is 0. Initialising maxi = 0 silently implements the second interpretation. Ask which one the problem wants — LC 53 requires a non-empty subarray, so maxi must start at negative infinity.

Interview Q&A
Why is discarding a negative prefix safe?

If a prefix sums to a negative value, any subarray that includes it would score higher by excluding it. So no optimal answer ever starts with a negative-sum prefix — dropping it can never lose the true maximum.

Is Kadane's algorithm dynamic programming?

Yes. Define dp[i] as the best subarray sum ending at i: dp[i] = max(arr[i], dp[i-1] + arr[i]). The answer is max(dp). Kadane is that recurrence with the array collapsed to a single variable — a space-optimised DP.

Maximum circular subarray sum (LC 918)?

The answer is either a normal Kadane result, or it wraps around — which means the complement is a minimum subarray. So compute max(kadaneMax, totalSum − kadaneMin). Edge case: if all elements are negative, totalSum − kadaneMin is 0 (empty), so return kadaneMax instead.

Is there a divide and conquer solution?

Yes — the maximum subarray is entirely in the left half, entirely in the right half, or crosses the midpoint; the crossing case is computed by expanding outward from the middle. O(N log N), which is why Kadane's O(N) is the celebrated result.

Maximum subarray of size exactly K?

Different problem — that is a fixed-size sliding window: sum the first K, then slide by adding the entering element and subtracting the leaving one. O(N).

Print the Subarray with Maximum Sum

Kadane extendedO(N) / O(1)Follow-up to B4

Same as Kadane, but return the actual subarray, not just its sum. This is the standard follow-up to B4 and it is entirely about index bookkeeping.

Input : arr = [-2, 1, -3, 4, -1, 2, 1, -5, 4] Output: [4, -1, 2, 1] (indices 3 to 6, sum 6)

Algorithm

  1. Run Kadane as before, but add a variable start.
  2. Whenever sum becomes 0 (i.e. you are about to begin a fresh block), set start = i. Because of the reset order, this means "the next element begins a candidate subarray".
  3. Whenever sum > maxi, record ansStart = start and ansEnd = i — the winning window at that moment.
  4. At the end, slice arr[ansStart .. ansEnd].
Kadane with indices
vector<int> maxSubarray(vector<int>& arr) {
    long long sum = 0, maxi = LLONG_MIN;
    int start = 0, ansStart = -1, ansEnd = -1;

    for (int i = 0; i < arr.size(); i++) {
        if (sum == 0) start = i;               // a fresh block begins here
        sum += arr[i];
        if (sum > maxi) {                      // new best - lock the window
            maxi = sum;
            ansStart = start;
            ansEnd = i;
        }
        if (sum < 0) sum = 0;                  // discard the liability
    }
    return vector<int>(arr.begin() + ansStart, arr.begin() + ansEnd + 1);
}
def max_subarray(arr):
    total, maxi = 0, float('-inf')
    start = ans_start = ans_end = 0

    for i, v in enumerate(arr):
        if total == 0:
            start = i                          # a fresh block begins here
        total += v
        if total > maxi:                       # new best - lock the window
            maxi = total
            ans_start, ans_end = start, i
        if total < 0:
            total = 0                          # discard the liability
    return arr[ans_start:ans_end + 1]
Time O(N)Space O(1)
Order of operations matters

if (sum == 0) start = i; must come before sum += arr[i]. Placing it after means start points one position too far right, and you print a subarray that is off by one — a bug that still produces the correct sum, so it passes a careless test.

Interview Q&A
What if several subarrays tie for the maximum?

Using strict > returns the earliest one; using >= returns the latest. Say which convention you chose — it shows you noticed the ambiguity.

Why not store all candidate subarrays and pick at the end?

That is O(N) extra space for no benefit. Two integers capture everything you need, which is the whole point of keeping Kadane at O(1).

Best Time to Buy and Sell Stock

LC 121Running minimumO(N) / O(1)

Given daily prices, buy on one day and sell on a later day for the maximum profit. If no profit is possible, return 0.

Input : prices = [7, 1, 5, 3, 6, 4] Output: 5 (buy at 1 on day 2, sell at 6 on day 5) Trace (mini = cheapest so far): 7 : mini=7 profit=0 1 : mini=1 profit=0 5 : mini=1 profit=4 3 : mini=1 profit=4 6 : mini=1 profit=5 ★ 4 : mini=1 profit=5 ✓

Brute force

Try every buy day i and every sell day j > i, tracking the largest difference. O(N²).

Optimal — track the minimum so far

Insight: on any given day, the best possible sale is today's price minus the cheapest price seen before today. One variable stores that cheapest price.

  1. mini = prices[0], profit = 0.
  2. For each day i from 1: profit = max(profit, prices[i] − mini).
  3. Then mini = min(mini, prices[i]).
  4. Return profit.
stock buy and sell
int maxProfit(vector<int>& prices) {
    if (prices.empty()) return 0;
    int mini = prices[0], profit = 0;
    for (int i = 1; i < prices.size(); i++) {
        profit = max(profit, prices[i] - mini);  // sell today at best-so-far buy
        mini   = min(mini, prices[i]);           // update cheapest day
    }
    return profit;                               // 0 if never profitable
}
def max_profit(prices):
    if not prices:
        return 0
    mini, profit = prices[0], 0
    for p in prices[1:]:

This is Kadane in disguise

Run Kadane on the array of daily differences prices[i] − prices[i−1] and you get exactly the same answer — the maximum subarray of daily changes is the best buy-sell window. Mentioning this connection is a strong signal in an interview.

Interview Q&A
Why does the order of the two updates matter?

You must compute the profit before updating mini with today's price. Otherwise you could "buy and sell on the same day", which the problem forbids. (With the order shown, buying and selling on the same day yields 0, so it never wins anyway — but the reasoning is what matters.)

Unlimited transactions allowed (LC 122)?

Greedily collect every upward move: sum max(0, prices[i] − prices[i−1]) over all i. Every rising step can be captured independently, so the greedy sum is optimal.

At most two transactions (LC 123)?

DP with four states — bought1, sold1, bought2, sold2 — updated in one pass. Generalises to at most K transactions (LC 188) with a 2K-state DP in O(NK).

What if prices only ever decrease?

profit stays 0 because it is initialised to 0 and never beaten. That is the intended answer: do not trade. Note this is the opposite convention from Kadane, where 0-initialisation was a bug — here it is the specification.

Rearrange Array Elements by Sign

LC 2149Index placementO(N)Two variants

Rearrange so that positives and negatives alternate, starting with a positive, while preserving the relative order within each sign group.

Variant 1 — EQUAL counts of positives and negatives: Input : arr = [3, 1, -2, -5, 2, -4] Output: [3, -2, 1, -5, 2, -4] Variant 2 — UNEQUAL counts: alternate as long as possible, then append the remaining elements of the surplus sign at the end. Input : arr = [1, 2, -4, -5, 3, 4] (4 pos, 2 neg) Output: [1, -4, 2, -5, 3, 4]

Variant 1 — equal counts, optimal one pass

Insight: positives must land at even indices 0, 2, 4… and negatives at odd indices 1, 3, 5…. Keep two write-pointers and place directly.

  1. Create a result array of size n. Set posIdx = 0, negIdx = 1.
  2. Scan the input once.
  3. If the element is positive, write it at posIdx and do posIdx += 2.
  4. Otherwise write it at negIdx and do negIdx += 2.

Variant 2 — unequal counts

  1. Separate the array into a positives list and a negatives list, preserving order.
  2. Let m = min(pos.size(), neg.size()). For i in 0..m−1, write pos[i] then neg[i].
  3. Append whatever is left over from the longer list, in order.
rearrange by sign — both variants
// VARIANT 1 - equal counts: single pass, direct placement
vector<int> rearrangeEqual(vector<int>& arr) {
    int n = arr.size();
    vector<int> res(n);
    int posIdx = 0, negIdx = 1;                 // even slots / odd slots
    for (int v : arr) {
        if (v > 0) { res[posIdx] = v; posIdx += 2; }
        else       { res[negIdx] = v; negIdx += 2; }
    }
    return res;
}

// VARIANT 2 - unequal counts: split, interleave, append the surplus
vector<int> rearrangeUnequal(vector<int>& arr) {
    vector<int> pos, neg, res;
    for (int v : arr) (v > 0 ? pos : neg).push_back(v);

    int m = min(pos.size(), neg.size());
    for (int i = 0; i < m; i++) { res.push_back(pos[i]); res.push_back(neg[i]); }
    for (int i = m; i < pos.size(); i++) res.push_back(pos[i]);   // leftovers
    for (int i = m; i < neg.size(); i++) res.push_back(neg[i]);
    return res;
}

def rearrange_unequal(arr):
    pos = [v for v in arr if v > 0]
    neg = [v for v in arr if v < 0]

"Are the counts of positives and negatives guaranteed equal?" and "Where does zero go?" Zero is neither positive nor negative — LC 2149 guarantees no zeros, but a GFG variant may not. One clarifying question saves a rewrite.

Interview Q&A
Can this be done in O(1) extra space while preserving order?

Not straightforwardly. Order-preserving in-place rearrangement requires rotations that push the cost to O(N²), or a cycle-based algorithm that is genuinely intricate. If order need not be preserved, a two-pointer swap does it in O(N)/O(1). State the trade-off — the interviewer is testing whether you claim O(1) space carelessly.

What does "preserving relative order" mean here?

Among positives alone, they appear in the same sequence as in the input; likewise among negatives. Interleaving changes absolute positions but not intra-group order.

Next Permutation

LC 31Pivot + swap + reverseO(N) / O(1)Frequently asked

Rearrange the array into the next lexicographically greater permutation. If none exists (the array is in descending order), rearrange to the smallest permutation (ascending).

Input : [1, 3, 5, 4, 2] → Output: [1, 4, 2, 3, 5] THE THREE STEPS: 1. Find the PIVOT — rightmost i with arr[i] < arr[i+1] [1, 3, 5, 4, 2] → i = 1 (value 3), because 3 < 5 ↑pivot 2. From the right, find the smallest value GREATER than the pivot; swap [1, 3, 5, 4, 2] → 4 > 3, swap → [1, 4, 5, 3, 2] 3. Reverse everything after the pivot (that suffix is descending → make it ascending) [1, 4, |5, 3, 2] → [1, 4, 2, 3, 5] ✓

Brute force

Generate all N! permutations, sort them, linear-search for the current one, return the next. Astronomically slow — mention it in one sentence purely to show you understand what "next permutation" means, then move on.

Optimal — the three-step algorithm

  1. Find the pivot. Scan from the right for the first index i where arr[i] < arr[i+1]. Everything to the right of the pivot is non-increasing — already the largest arrangement of those values.
  2. No pivot? The whole array is descending — it is the last permutation. Reverse it entirely and return.
  3. Swap. Scan from the right again for the first element strictly greater than arr[i], and swap them. Because the suffix is sorted descending, the first such element from the right is the smallest one that qualifies.
  4. Reverse the suffix from i+1 to the end, turning the largest arrangement into the smallest.
next permutation
void nextPermutation(vector<int>& arr) {
    int n = arr.size(), i = n - 2;

    // STEP 1 - find the pivot: rightmost i with arr[i] < arr[i+1]
    while (i >= 0 && arr[i] >= arr[i + 1]) i--;

    // STEP 2 - if a pivot exists, swap it with the next bigger value from the right
    if (i >= 0) {
        int j = n - 1;
        while (arr[j] <= arr[i]) j--;          // suffix is descending
        swap(arr[i], arr[j]);
    }
    // STEP 3 - reverse the suffix (descending -> ascending = smallest)
    reverse(arr.begin() + i + 1, arr.end());
    // If no pivot was found, i = -1 and this reverses the whole array. Correct!
}
def next_permutation(arr):
    n = len(arr)
    i = n - 2

    # STEP 1 - find the pivot: rightmost i with arr[i] < arr[i+1]
    while i >= 0 and arr[i] >= arr[i + 1]:
        i -= 1

    # STEP 2 - if a pivot exists, swap with the next bigger value from the right
    if i >= 0:
        j = n - 1
        while arr[j] <= arr[i]:                # suffix is descending
            j -= 1
        arr[i], arr[j] = arr[j], arr[i]

    # STEP 3 - reverse the suffix (descending -> ascending = smallest)
    arr[i + 1:] = reversed(arr[i + 1:])
    # If no pivot was found, i = -1 and this reverses the whole array. Correct!
Time O(N)Space O(1)
Memory hook: "break point, swap, reverse"

Say it as a story: "Find the rightmost place where the sequence stops descending — that is the only digit worth increasing. Increase it as little as possible, then make everything after it as small as possible." That sentence is the proof of correctness, and it is what you narrate while coding.

Interview Q&A
Why must the suffix after the pivot be non-increasing?

By construction — the pivot is defined as the rightmost index where an increase occurs, so to its right no increase exists. That is what makes step 3 a simple reverse rather than a sort.

Why does swapping with the rightmost greater element give the next permutation and not a later one?

Since the suffix descends, scanning from the right finds the smallest value that still exceeds the pivot. Swapping in anything larger would skip over valid permutations.

Previous permutation — how?

Mirror every comparison: find the rightmost i with arr[i] > arr[i+1], swap with the rightmost element smaller than it, then reverse the suffix.

How does the STL do it?

std::next_permutation(arr.begin(), arr.end()) — the exact same algorithm, returning false when it wraps around to the first permutation. Mention that you know it exists, but write the algorithm out; that is what is being tested.

What about duplicate values?

Handled automatically by the non-strict comparisons (>= in step 1 and <= in step 2). Those two operators are exactly what makes duplicates work — swapping them for strict versions breaks it.

Leaders in an Array

GFGSuffix scanO(N) / O(1)

An element is a leader if it is greater than every element to its right. The rightmost element is always a leader.

Input : arr = [10, 22, 12, 3, 0, 6] Output: [22, 12, 6] Scan RIGHT to LEFT, tracking the maximum seen so far: 6 > -inf → leader, maxi=6 0 < 6 → not 3 < 6 → not 12 > 6 → leader, maxi=12 22 > 12 → leader, maxi=22 10 < 22 → not reverse the collected list → [22, 12, 6] ✓

Brute force

For each element, scan everything to its right to check it is the biggest. O(N²).

Optimal — traverse from the right

Insight: "greater than everything to the right" only depends on the maximum to the right. Walking backwards lets you maintain that maximum in a single variable.

  1. maxi = INT_MIN.
  2. Loop i from n−1 down to 0.
  3. If arr[i] > maxi, it is a leader — record it and set maxi = arr[i].
  4. Reverse the collected list to restore original left-to-right order.

vector<int> leaders(vector<int>& arr) {
    vector<int> res;
    int maxi = INT_MIN;
    for (int i = arr.size() - 1; i >= 0; i--) {   // walk RIGHT to LEFT
        if (arr[i] > maxi) {                      // beats everything to its right
            res.push_back(arr[i]);
            maxi = arr[i];
        }
    }
    reverse(res.begin(), res.end());              // restore original order
    return res;
}

The transferable lesson

When a condition depends on "everything to the right", traverse from the right. This one habit solves leaders, next greater element (with a stack), suffix maximum/minimum, rain-water trapping and stock-span problems.

Interview Q&A
Should an element equal to the maximum on its right count as a leader?

Depends on whether the definition says "greater" or "greater than or equal". GFG uses >= in some versions. Ask, then use > or >= accordingly — it is a one-character difference that flips test cases.

How is this related to Next Greater Element?

A leader is exactly an element with no next greater element to its right. The stack-based NGE algorithm produces leaders as a by-product — whatever remains in the stack at the end is the set of leaders.

Can you avoid the final reverse?

Yes — insert at the front of a deque, or collect indices and emit in ascending order. The reverse costs O(N) anyway, so it does not change the complexity; the deque version is just tidier.

Longest Consecutive Sequence

LC 128Hash setO(N)Tricky complexity

Find the length of the longest run of consecutive integers present in the array. The array is unsorted, and the elements of the run do not have to be adjacent.

Input : arr = [100, 4, 200, 1, 3, 2] Output: 4 (the sequence 1, 2, 3, 4) Set-based scan — only START from a number whose predecessor is absent: 100 : is 99 in the set? no → it's a start. 101? no. length 1 4 : is 3 in the set? YES → skip, it's mid-sequence 200 : is 199 present? no → start. 201? no. length 1 1 : is 0 present? no → start. 2✓ 3✓ 4✓ 5✗ → length 4 ★

Brute force

For each element, repeatedly search the array for value+1, value+2, … O(N³) in the worst case (a linear search inside a linear walk inside a loop).

Better — sort first

Sort, then walk through counting consecutive runs and skipping duplicates. O(N log N) time, O(1) space. A perfectly good answer — say it out loud before giving the optimal one.

Optimal — hash set with the "start only" trick

  1. Put every element into a hash set (this also removes duplicates).
  2. For each value v in the set, check whether v − 1 is also present.
  3. If it is, v sits in the middle of a run — skip it entirely.
  4. If it is not, v starts a run: count upward v+1, v+2, … while each is present.
  5. Track the longest run found.
longest consecutive sequence
int longestConsecutive(vector<int>& arr) {
    if (arr.empty()) return 0;
    unordered_set<int> s(arr.begin(), arr.end());   // dedupes for free
    int best = 0;

    for (int v : s) {
        if (s.count(v - 1)) continue;               // not a start - skip it
        int cur = v, len = 1;                       // v starts a run
        while (s.count(cur + 1)) { cur++; len++; }
        best = max(best, len);
    }
    return best;
}

Why this is O(N) despite the nested while loop

The inner loop only runs for values that start a sequence, and it walks each sequence exactly once. Across the whole algorithm, every element is visited by an inner loop at most once, so total inner work is O(N). This is the question interviewers ask — "isn't that O(N²)?" — and the amortised answer is the entire point of the problem. Without the v − 1 check it genuinely would be O(N²).

Interview Q&A
Why iterate over the set rather than the array?

Duplicates in the array would make you redo identical work. The set has each value once, keeping the amortised argument clean.

Is the true worst case really O(N)?

O(N) average — hash collisions could degrade lookups. The guaranteed alternative is the sorting solution at O(N log N). Stating both, and which you would ship, is the mature answer.

What about negative numbers?

Works unchanged — a hash set has no range restriction. That is precisely why an "index as hash" trick will not work here, and why hashing is the right tool.

Can you also return the sequence itself?

Record the starting value alongside the best length, then regenerate start, start+1, …, start+len−1 at the end. No extra asymptotic cost.

Set Matrix Zeroes

LC 73MatrixO(M×N) / O(1)Classic trap

If any cell is 0, set its entire row and column to 0 — in place.

Input : [[1, 1, 1], Output: [[1, 0, 1], [1, 0, 1], [0, 0, 0], [1, 1, 1]] [1, 0, 1]] THE TRAP: if you zero a row immediately, the new zeros are indistinguishable from original zeros, and the next scan wipes the whole matrix. You MUST mark first and zero later.

Brute force

For each 0, mark its row and column with a placeholder value like −1, then convert placeholders to 0 at the end. O((M×N)×(M+N)), and it breaks if −1 is a legal matrix value.

Better — two marker arrays

  1. Create row[M] and col[N], all false.
  2. First pass: for every 0 at (i, j), set row[i] = true and col[j] = true.
  3. Second pass: set mat[i][j] = 0 whenever row[i] or col[j] is true.
Time O(M×N)Space O(M+N)

Optimal — use the first row and column as the markers

Insight: the marker arrays can live inside the matrix itself. Row 0 stores the column flags and column 0 stores the row flags. The only conflict is cell (0,0), which both would want — so give it to the rows and keep a separate variable col0 for column 0.

  1. Scan the matrix. On finding a 0 at (i, j): set mat[i][0] = 0, and set mat[0][j] = 0 if j != 0, else set col0 = 0.
  2. Fill the interior from (1,1) outward, checking mat[i][0] and mat[0][j].
  3. Then handle row 0 using mat[0][0].
  4. Finally handle column 0 using col0. Order matters — doing the first row/column before the interior destroys the markers.

void setZeroes(vector<vector<int>>& mat) {
    int m = mat.size(), n = mat[0].size(), col0 = 1;

    // PASS 1 - record flags inside row 0 and column 0
    for (int i = 0; i < m; i++) {
        for (int j = 0; j < n; j++) {
            if (mat[i][j] == 0) {
                mat[i][0] = 0;                  // flag the row
                if (j != 0) mat[0][j] = 0;      // flag the column
                else        col0 = 0;           // (0,0) clash -> separate var
            }
        }
    }
    // PASS 2 - fill the INTERIOR first (markers still intact)

    if (mat[0][0] == 0) for (int j = 0; j < n; j++) mat[0][j] = 0;
    if (col0 == 0)      for (int i = 0; i < m; i++) mat[i][0] = 0;
}

Why the interior loop runs backwards

Filling from the bottom-right inward guarantees you never overwrite a marker before reading it. Going forward from (1,1) also works because you only ever read row 0 and column 0 — but the reverse order makes the safety obvious and is the version to write under pressure.

Interview Q&A
Why is a single variable enough for the (0,0) conflict?

Because there is exactly one overlapping cell. mat[0][0] serves the first row's flag, and col0 serves the first column's flag. One extra boolean is O(1) space.

Why can't you zero rows as you find them?

The zeros you write are indistinguishable from original zeros, so subsequent scanning treats them as new triggers and cascades until the entire matrix is 0. This "mark first, apply later" discipline recurs across in-place matrix problems.

Is O(M+N) space acceptable?

Yes — it is the expected "better" solution and many interviewers stop there. Offer it, then say "and I can push it to O(1) by storing the flags in the first row and column." That sequencing earns full marks.

LC 48Transpose + reverseO(N²) / O(1)Must know

Rotate an N×N matrix 90° clockwise, in place.

Input : [[1,2,3], Output: [[7,4,1], [4,5,6], [8,5,2], [7,8,9]] [9,6,3]] STEP 1 — TRANSPOSE (mirror across the main diagonal): [[1,2,3], [[1,4,7], [4,5,6], → [2,5,8], [7,8,9]] [3,6,9]] STEP 2 — REVERSE EACH ROW: [[1,4,7], [[7,4,1], [2,5,8], → [8,5,2], [3,6,9]] [9,6,3]] ✓

Brute force

Allocate a new N×N matrix and place mat[i][j] at res[j][n-1-i]. Simple and correct — O(N²) time and O(N²) space. Derive that index mapping on paper; it is worth knowing regardless.

Optimal — transpose, then reverse each row

  1. Transpose: for i from 0 to n−1, for j from i+1 to n−1, swap mat[i][j] with mat[j][i]. Starting j at i+1 is essential — starting at 0 swaps every pair twice and undoes the work.
  2. Reverse each row individually.
rotate 90° clockwise
void rotate(vector<vector<int>>& mat) {
    int n = mat.size();

    // STEP 1 - transpose (only the upper triangle, or you undo yourself)
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            swap(mat[i][j], mat[j][i]);

    // STEP 2 - reverse every row
    for (int i = 0; i < n; i++)
        reverse(mat[i].begin(), mat[i].end());
}

// ANTICLOCKWISE: transpose, then reverse each COLUMN
// (equivalently: reverse the row ORDER first, then transpose)

Clockwise = transpose then reverse rows. Anticlockwise = transpose then reverse columns. If you ever blank, rotate a 2×2 on scrap paper — it takes eight seconds and settles the direction for certain.

Interview Q&A
What breaks if the inner loop starts at j = 0?

Each pair (i,j) and (j,i) gets swapped twice, returning the matrix to its original state. The transpose becomes a no-op and the final result is just each row reversed.

How do you rotate a non-square M×N matrix?

You cannot do it in place — the dimensions change from M×N to N×M. Allocate a new matrix and use res[j][m-1-i] = mat[i][j]. Pointing out that in-place is impossible here is exactly the kind of observation interviewers reward.

Rotate by 180°?

Apply the 90° rotation twice, or more directly: reverse the order of the rows and reverse each row. O(N²) either way.

What is the layer-by-layer four-way swap approach?

Rotate concentric rings, moving four elements at a time with one temporary. Same complexity but four index expressions to get right under pressure, versus two clean steps. Mention it, then write transpose + reverse.

  2. While top <= bottom and left <= right:

vector<int> spiralOrder(vector<vector<int>>& mat) {
    vector<int> res;
    if (mat.empty()) return res;
    int m = mat.size(), n = mat[0].size();
    int top = 0, bottom = m - 1, left = 0, right = n - 1;

    while (top <= bottom && left <= right) {
        for (int j = left; j <= right; j++) res.push_back(mat[top][j]);
        top++;
        for (int i = top; i <= bottom; i++) res.push_back(mat[i][right]);
        right--;
        if (top <= bottom) {                        // GUARD - single row left?
            for (int j = right; j >= left; j--) res.push_back(mat[bottom][j]);
            bottom--;
        }
        if (left <= right) {                        // GUARD - single column left?
            for (int i = bottom; i >= top; i--) res.push_back(mat[i][left]);
            left++;
        }
    }
    return res;

Interview Q&A
Why are guards needed on the third and fourth walks but not the first two?

Because the loop condition was checked before walk 1, and walk 2 is protected by top++ having already happened. By walk 3 the boundaries have moved twice, so a single remaining row could be revisited. Guarding those two is exactly sufficient.

Generate a spiral matrix instead of reading one (LC 59)?

Optimal — prefix sum + frequency map

Why seed the map with {0 : 1}?

It represents the empty prefix before index 0. Without it, a subarray that starts at index 0 and sums to K is never counted — for example [3] with k = 3 would return 0.

Why not a sliding window?

Negatives break the monotonic growth a window depends on. If the problem guaranteed all-positive values, a window would work and would use O(1) space — always ask about negatives first.

Pascal's Triangle

LC 118 / 119CombinatoricsO(N²)Three variants

Pascal's triangle asks three different questions, and interviewers pick one deliberately:

1 row 1 1 1 row 2 1 2 1 row 3 1 3 3 1 row 4 1 4 6 4 1 row 5 VARIANT 1 : the element at row r, column c → O(c) formula VARIANT 2 : the entire r-th row → O(N) running product VARIANT 3 : the whole triangle up to N rows → O(N²) build up

Variant 1 — one element

The value at row r, column c (1-indexed) is the binomial coefficient C(r−1, c−1). Computing it with factorials risks overflow, so build it iteratively: C(n, r) = C(n, r−1) × (n − r + 1) / r.

Variant 2 — one whole row in O(N)

Insight: each element in a row is derivable from the previous one. Start at 1 and multiply by (rowIndex − i) / (i + 1) stepwise. No nested loop, no factorials.

Variant 3 — the full triangle

Row i has i elements; the first and last are 1, and every interior element is the sum of the two above it.

What does row N sum to?

2N−1 for the N-th row (1-indexed), because the row is the binomial expansion of (1+1)N−1. A nice sanity check for your output.

Space-optimise the full triangle to O(N)?

If only the final row is needed, update one array in place, iterating backwards so each cell reads its old left-neighbour before that neighbour is overwritten. Same trick as space-optimised 0/1 knapsack.

Where does Pascal's triangle show up elsewhere?

Binomial coefficients in probability, combinations C(n,r) in counting problems, the Fibonacci numbers along its shallow diagonals, and the coefficients of polynomial expansions.

Majority Element (> N/3 times)

LC 229Extended Moore'sO(N) / O(1)

Find all elements appearing more than ⌊N/3⌋ times. Key observation: there can be at most two such elements — three of them would need more than N votes.

Input : arr = [11, 33, 33, 11, 33, 11] Output: [11, 33] (each appears 3 times, and 3 > 6/3 = 2) Why at most 2? If three elements each had > N/3 occurrences, the total would exceed 3 × N/3 = N. Impossible.

Brute force / better

Count each element with a nested loop → O(N²). Or use a hashmap of frequencies and collect keys with count > n/3 → O(N) time, O(N) space. The map version is a solid answer; the O(1)-space version is the one they are fishing for.

Optimal — Boyer–Moore with two counters

  1. Keep cnt1, el1, cnt2, el2, with counts starting at 0 and the elements set to impossible sentinels.
  2. For each value v: if v == el1, cnt1++; else if v == el2, cnt2++.
  3. Else if cnt1 == 0 adopt v as el1 (with count 1); else if cnt2 == 0 adopt it as el2.
  4. Otherwise decrement both counters — a three-way cancellation.
  5. Verify with a second pass, since surviving candidates are only possible answers.

Order matters: the equality checks must come before the zero checks, or the same value can be adopted into both slots.

majority n/3 — two candidates
vector<int> majorityElementN3(vector<int>& arr) {
    int cnt1 = 0, cnt2 = 0;
    long long el1 = LLONG_MIN, el2 = LLONG_MIN;   // impossible sentinels

    for (int v : arr) {                            // PASS 1 - find candidates
        if      (cnt1 > 0 && el1 == v) cnt1++;     // equality checks FIRST
        else if (cnt2 > 0 && el2 == v) cnt2++;
        else if (cnt1 == 0) { el1 = v; cnt1 = 1; }
        else if (cnt2 == 0) { el2 = v; cnt2 = 1; }
        else { cnt1--; cnt2--; }                   // three-way cancellation
    }

    vector<int> res;                               // PASS 2 - verify
    int c1 = 0, c2 = 0;
    for (int v : arr) { if (v == el1) c1++; if (v == el2) c2++; }
    int need = arr.size() / 3 + 1;
    if (c1 >= need) res.push_back((int)el1);
    if (c2 >= need && el2 != el1) res.push_back((int)el2);
    sort(res.begin(), res.end());
    return res;
}
def majority_element_n3(arr):
    cnt1 = cnt2 = 0
    el1 = el2 = None                               # impossible sentinels

    for v in arr:                                  # PASS 1 - find candidates
        if cnt1 > 0 and el1 == v:                  # equality checks FIRST
            cnt1 += 1
        elif cnt2 > 0 and el2 == v:
            cnt2 += 1
        elif cnt1 == 0:
            el1, cnt1 = v, 1
        elif cnt2 == 0:
            el2, cnt2 = v, 1
        else:
            cnt1 -= 1                              # three-way cancellation
            cnt2 -= 1

    res = []                                       # PASS 2 - verify
    need = len(arr) // 3 + 1
    for cand in {el1, el2}:
        if cand is not None and arr.count(cand) >= need:
            res.append(cand)
    return sorted(res)

The general rule worth memorising

"More than N/K times" allows at most K−1 answers, and needs K−1 counters. N/2 → one counter (B3). N/3 → two counters (C2). N/4 → three counters. Stating this generalisation unprompted is a strong signal.

Interview Q&A
Why is the verification pass mandatory here, even more than in B3?

Because the problem does not promise that any qualifying element exists — [1, 2, 3] has none. The algorithm still produces two candidates, so without verification you return garbage.

Why must the equality checks precede the zero checks?

Otherwise, when cnt1 drops to 0 and the same value arrives again, it could be adopted as el2 while el1 still holds it — corrupting both slots with duplicates and losing a genuine second candidate.

Why decrement both counters at once?

The cancellation is three-way: one vote for candidate 1, one for candidate 2, and the current outsider all annihilate together. Since only elements exceeding N/3 can survive N/3 such triples, the true answers cannot be eliminated.

3 Sum — Triplets Summing to Zero

LC 15Sort + two pointersO(N²)Duplicate handling

Find all unique triplets that sum to zero. "Unique" is the hard part — the algorithm is easy, the duplicate handling is where candidates lose the round.

Input : arr = [-1, 0, 1, 2, -1, -4] Output: [[-1, -1, 2], [-1, 0, 1]] After sorting: [-4, -1, -1, 0, 1, 2] i=0 (-4): need 4 from the rest → no pair found i=1 (-1): l=2, r=5 → -1 + -1 + 2 = 0 ✓ record, then SKIP duplicates → -1 + 0 + 1 = 0 ✓ record i=2 (-1): SAME as i=1 → skip entirely (would duplicate the answer)

Brute force / better

Three nested loops with a set to deduplicate → O(N³). Or two loops plus a hash set for the third value → O(N²) time and O(N) space. Both are worth naming before the optimal.

Optimal — sort, fix one, two-pointer the rest

  1. Sort the array. This makes duplicates adjacent and enables two pointers.
  2. Fix i from 0 to n−3. If arr[i] == arr[i−1], skip — that outer value was already fully explored.
  3. Set l = i + 1, r = n − 1.
  4. If the triplet sum is too small, l++; too big, r--.
  5. If it is exactly zero, record it, then advance l past all equal values and retreat r past all equal values.

vector<vector<int>> threeSum(vector<int>& arr) {
    sort(arr.begin(), arr.end());
    int n = arr.size();
    vector<vector<int>> res;

    for (int i = 0; i < n - 2; i++) {
        if (i > 0 && arr[i] == arr[i - 1]) continue;   // skip duplicate anchor
        int l = i + 1, r = n - 1;
        while (l < r) {
            long long sum = (long long)arr[i] + arr[l] + arr[r];

            else if (sum > 0) r--;

                res.push_back({arr[i], arr[l], arr[r]});

                while (l < r && arr[l] == arr[l - 1]) l++;   // skip dup left
                while (l < r && arr[r] == arr[r + 1]) r--;   // skip dup right

        }
    }

Three duplicate skips, all required

One for the outer anchor i, one for l, one for r. Miss any of them and you emit repeated triplets. Note the direction of each comparison: arr[l] == arr[l−1] looks backwards, arr[r] == arr[r+1] looks forwards — because the pointers moved in opposite directions just before the check.

Interview Q&A
Why is sorting worth its O(N log N) cost here?

Because the outer loop is already O(N²), so the sort is asymptotically free. In exchange it makes duplicates adjacent (easy to skip) and makes the two-pointer scan valid — two problems solved by one preprocessing step.

Can you do better than O(N²)?

Not by any known general method — 3-sum is conjectured to require Ω(N²) in the standard model, and it is a classic reduction target in computational geometry. Saying "O(N²) is believed optimal" is the correct answer.

Why use a set to deduplicate rather than skipping?

You can — insert sorted triplets into a set — but it adds O(N²) space and a log factor. Pointer skipping achieves the same with O(1) extra space, and demonstrating it is the point of the exercise.

Target is T instead of 0?

Compare against T instead of 0 — nothing else changes. Watch for overflow when values are large: cast the sum to long long.

Largest Subarray with Sum Zero

GFGPrefix + hashmapO(N)

Find the length of the longest subarray whose elements sum to zero. This is A14 with k = 0 — recognising that is the whole solution.

Input : arr = [9, -3, 3, -1, 6, -5] Output: 5 ([-3, 3, -1, 6, -5] sums to 0) Prefix sums: 9, 6, 9, 8, 14, 9 ↑ ↑ ↑ prefix 9 appears at index 0, 2 and 5. Between two equal prefixes, the sum is ZERO. Longest gap: index 0 → 5 gives length 5 ✓

Optimal — equal prefix sums

Insight: if the prefix sum at index i equals the prefix sum at index j, everything between them sums to zero. So the task is "find the two farthest-apart equal prefix sums."

  1. Keep a map from prefix sum → earliest index at which it occurred.
  2. Maintain a running sum.
  3. If sum == 0, the whole prefix qualifies: maxLen = i + 1.
  4. Else if sum is already in the map, update maxLen = max(maxLen, i − map[sum]).
  5. Else store map[sum] = i. Never overwrite — an earlier index gives a longer span.

int maxLenZeroSum(vector<int>& arr) {

    long long sum = 0;
    int maxLen = 0;

    for (int i = 0; i < arr.size(); i++) {
        sum += arr[i];
        if (sum == 0) {
            maxLen = i + 1;                       // whole prefix sums to zero
        } else if (firstIdx.count(sum)) {
            maxLen = max(maxLen, i - firstIdx[sum]);   // gap between equals
        } else {
            firstIdx[sum] = i;                    // store ONLY the first time
        }
    }
    return maxLen;
}

Brute force / better

All subarrays with an inner XOR → O(N³); running XOR in the inner loop → O(N²).

Optimal — prefix XOR + frequency map

  1. Seed the map with {0 : 1}, the empty prefix.
  2. Maintain a running XOR X.
  3. At each index, add map[X ^ k] to the count.
  4. Then increment map[X].

int subarraysWithXorK(vector<int>& arr, int k) {
    unordered_map<int, int> freq;
    freq[0] = 1;                       // empty prefix
    int X = 0, count = 0;

    for (int v : arr) {
        X ^= v;                        // running prefix XOR
        int need = X ^ k;              // because  need ^ k == X
        if (freq.count(need)) count += freq[need];
        freq[X]++;
    }
    return count;
}

XOR is its own inverse (a ^ b ^ b = a), so there is no subtraction and no overflow — the running value never exceeds the largest input. It is the cleanest member of the prefix-sum family.

Merge Overlapping Intervals

LC 56Sort + greedyO(N log N)Very common

Merge all overlapping intervals and return the non-overlapping set covering the same ground.

Input : [[1,3], [2,6], [8,10], [15,18]] Output: [[1,6], [8,10], [15,18]] After sorting by START: [1,3] → open a block: current = [1,3] [2,6] → 2 <= 3 → OVERLAP → extend end to max(3,6) = 6 → [1,6] [8,10] → 8 > 6 → no overlap → close [1,6], open [8,10] [15,18] → 15 > 10 → close [8,10], open [15,18]

Brute force

Sort, then for each interval scan forward merging anything that overlaps, with an inner loop. O(N²) and fiddly — the greedy version below is both shorter and faster.

Optimal — sort by start, then one greedy pass

  1. Sort intervals by their start value. This is the entire trick: after sorting, any interval that overlaps the current block must overlap it immediately.
  2. Put the first interval into the result as the open block.
  3. For each subsequent interval: if start <= result.back().end, they overlap → extend with end = max(end, current.end).
  4. Otherwise there is a gap → push it as a new block.

vector<vector<int>> mergeIntervals(vector<vector<int>>& intervals) {

            res.push_back(intervals[i]);             // gap - start a new block

Merge Two Sorted Arrays Without Extra Space

LC 88Gap methodO((N+M)·log(N+M))Hard

Given sorted arrays a (size n) and b (size m), merge them so a holds the smallest n elements and b the largest m — without allocating a third array.

Input : a = [1, 4, 8, 10], b = [2, 3, 9] Output: a = [1, 2, 3, 4], b = [8, 9, 10] GAP METHOD (Shell-sort flavoured): total = 7, gap = ceil(7/2) = 4 gap=4 : compare (0,4)(1,5)(2,6) across the virtual joined array → swap if out of order gap=2 : compare (0,2)(1,3)(2,4)(3,5)(4,6) gap=1 : compare adjacent pairs → fully sorted Each pass halves the gap → log(N+M) passes.

Brute force

Merge into a third array and copy back. O(N+M) time but O(N+M) space — which is exactly what the problem forbids.

Better — two pointers with swaps

  1. Point i at the last element of a and j at the first of b.
  2. While a[i] > b[j], swap them and move i--, j++.
  3. Stop as soon as the comparison fails — after that, a holds the small values and b the large ones, but each is now unsorted.
  4. Sort both arrays.
Time O(min(N,M) + N log N + M log M)Space O(1)

Optimal — the gap method

Insight: treat the two arrays as one virtual array of length n + m. Start with a gap of ceil((n+m)/2), compare and swap every pair separated by that gap, then halve the gap and repeat until it reaches 1. This is a Shell sort on data that is already mostly ordered, so it converges in log passes.

gap method
void swapIfGreater(vector<int>& a, vector<int>& b, int i, int j) {
    if (a[i] > b[j]) swap(a[i], b[j]);
}

void mergeNoExtraSpace(vector<int>& a, vector<int>& b) {
    int n = a.size(), m = b.size(), total = n + m;
    int gap = (total / 2) + (total % 2);            // ceil(total / 2)

    while (gap > 0) {
        int left = 0, right = left + gap;
        while (right < total) {
            if (left < n && right >= n)             // one in a, one in b
                swapIfGreater(a, b, left, right - n);
            else if (left >= n)                     // both inside b
                swapIfGreater(b, b, left - n, right - n);
            else                                    // both inside a
                swapIfGreater(a, a, left, right);
            left++; right++;
        }
        if (gap == 1) break;                        // finished
        gap = (gap / 2) + (gap % 2);                // halve, rounding up
    }
}

Interview Q&A
Why must the gap be rounded up?

Rounding down can make the gap reach 0 before the array is sorted (for example 1/2 = 0), terminating early with wrong output. Ceiling guarantees the sequence ends at exactly 1 and every adjacent pair is compared.

Why does filling from the back work in LC 88?

The tail of a is empty, so writing there destroys nothing. Going backwards, the position you are about to write is always at or beyond both read pointers — no data is overwritten before it is used. Writing forwards would clobber unread elements of a.

Why is the gap method O((N+M)log(N+M)) and not O(N+M)?

Each pass costs O(N+M), and the gap halves each time, giving log(N+M) passes. It is a Shell sort with a specific gap sequence, exploiting the fact that both halves are already sorted.

An array of size N should contain each number from 1 to N exactly once. Instead, one number X appears twice and another number Y is missing. Find both.

Input : arr = [3, 1, 2, 5, 3] (N = 5) Output: repeating = 3, missing = 4 MATHS APPROACH — two equations, two unknowns: S = sum(arr) − sum(1..N) = X − Y S2 = sum(arr²) − sum(1..N²) = X² − Y² = (X+Y)(X−Y) So X + Y = S2 / S Then X = (S + S2/S) / 2 and Y = X − S

Brute force / better

Count occurrences of each value 1..N with a nested loop → O(N²). Or use a frequency array of size N+1 → O(N) time, O(N) space. The map version is fine as your "better" rung.

Optimal 1 — the two-equation method

  1. Compute S = Σarr − N(N+1)/2, which equals X − Y.
  2. Compute S2 = Σarr² − N(N+1)(2N+1)/6, which equals X² − Y².
  3. Since X² − Y² = (X+Y)(X−Y), we get X + Y = S2 / S.
  4. Solve: X = (S + S2/S) / 2, then Y = X − S.
  5. Use long long — the sum of squares for N = 105 is around 3×1014.

Optimal 2 — XOR partitioning (no overflow)

  1. XOR all array elements with all numbers 1..N. Everything cancels except X ^ Y.
  2. Isolate any set bit of X ^ Y — that bit differs between X and Y, so it separates them.
  3. Partition both the array and the range 1..N into two buckets by that bit, XOR-ing each bucket.
  4. The two results are X and Y (in some order). One final scan of the array tells you which is the repeater.
repeating and missing — both methods
// METHOD 1 - maths.  long long is mandatory here.
vector<int> findMissingRepeatingMath(vector<int>& arr) {
    long long n = arr.size();
    long long Sn  = n * (n + 1) / 2;               // sum 1..n
    long long S2n = n * (n + 1) * (2 * n + 1) / 6; // sum of squares 1..n
    long long S = 0, S2 = 0;
    for (int v : arr) { S += v; S2 += 1LL * v * v; }

    long long diff = S - Sn;                       // X - Y
    long long sum  = (S2 - S2n) / diff;            // X + Y
    long long X = (diff + sum) / 2;
    long long Y = X - diff;
    return {(int)X, (int)Y};                       // {repeating, missing}
}

// METHOD 2 - XOR partitioning.  No overflow, ever.
vector<int> findMissingRepeatingXor(vector<int>& arr) {
    int n = arr.size(), xr = 0;
    for (int v : arr) xr ^= v;
    for (int i = 1; i <= n; i++) xr ^= i;          // xr = X ^ Y

    int bit = xr & -xr;                            // isolate lowest set bit
    int zero = 0, one = 0;
    for (int v : arr)            (v & bit ? one : zero) ^= v;
    for (int i = 1; i <= n; i++) (i & bit ? one : zero) ^= i;

    int cnt = 0;                                   // which one repeats?
    for (int v : arr) if (v == zero) cnt++;
    return cnt > 1 ? vector<int>{zero, one} : vector<int>{one, zero};
}

        xr ^= v

        else:       zero ^= v
    for i in range(1, n + 1):

        else:       zero ^= i

Overflow is the whole difficulty of method 1

For N = 105: the sum is about 5×109 (already past 32-bit int) and the sum of squares about 3.3×1014. Both need 64-bit types in C++/Java. This is precisely why the XOR method is the safer answer to give, even though the maths method is easier to derive on the spot.

Interview Q&A
Why does dividing by diff never fail?

Because X ≠ Y by the problem's definition — one repeats and a different one is missing — so X − Y ≠ 0. Worth stating explicitly; interviewers check whether you noticed the division.

Is there a third approach without maths or XOR?

Yes — index marking: for each value v, negate arr[abs(v)−1]. If it is already negative, abs(v) is the repeater; the index that stays positive is the missing number. O(N)/O(1), but it mutates the input, so mention that trade-off.

Explain xr & -xr once more.

It isolates the lowest set bit. Since xr = X ^ Y and X ≠ Y, at least one bit differs, so xr ≠ 0 and a set bit always exists. That bit is 1 in exactly one of X and Y, which is what makes the partition clean.

Count Inversions

GFG / CodeStudioMerge sortO(N log N)Hard

Count the pairs (i, j) with i < j and arr[i] > arr[j]. Informally: how far the array is from being sorted.

Input : arr = [5, 3, 2, 1, 4] Output: 7 pairs: (5,3)(5,2)(5,1)(5,4)(3,2)(3,1)(2,1) THE KEY MERGE INSIGHT: left = [3, 5] right = [1, 2, 4] ↑ i ↑ j If left[i] > right[j], then EVERY remaining element of the left half is also > right[j], because the left half is sorted. So add (mid − i + 1) inversions in ONE step, not one at a time.

Brute force

Two nested loops counting every offending pair. O(N²) — fine for N ≤ 5000 but nothing more.

Optimal — count during merge sort

Insight: merge sort already compares elements from the left half against the right half exactly once each. If left[i] > right[j], then because the left half is sorted, all mid − i + 1 remaining left elements also exceed right[j]. Add them all at once.

  1. Recursively sort and count the left half and the right half.
  2. Merge them; whenever left[i] > right[j], add (mid − i + 1) to the count and take from the right.
  3. Return the sum of the left count, right count, and cross count.
count inversions via merge sort
long long mergeAndCount(vector<int>& a, int low, int mid, int high) {
    vector<int> temp;
    int i = low, j = mid + 1;
    long long count = 0;

    while (i <= mid && j <= high) {
        if (a[i] <= a[j]) temp.push_back(a[i++]);      // no inversion
        else {
            count += (mid - i + 1);                   // ALL remaining left > a[j]
            temp.push_back(a[j++]);
        }
    }
    while (i <= mid)  temp.push_back(a[i++]);
    while (j <= high) temp.push_back(a[j++]);
    for (int k = low; k <= high; k++) a[k] = temp[k - low];
    return count;
}

def count_inversions(arr):

    def merge_and_count(low, mid, high):
        temp, i, j, count = [], low, mid + 1, 0
        while i <= mid and j <= high:
            if a[i] <= a[j]:
                temp.append(a[i]); i += 1             # no inversion
            else:
                count += (mid - i + 1)                # ALL remaining left > a[j]
                temp.append(a[j]); j += 1
        while i <= mid:
            temp.append(a[i]); i += 1
        while j <= high:
            temp.append(a[j]); j += 1
        a[low:high + 1] = temp
        return count

    def sort_count(low, high):
        if low >= high:
            return 0
        mid = (low + high) // 2
        return (sort_count(low, mid) + sort_count(mid + 1, high)
                + merge_and_count(low, mid, high))

    return sort_count(0, len(a) - 1)

The line that is the whole problem

count += (mid - i + 1); — counting a whole block of inversions in one operation is what turns O(N²) into O(N log N). If you can explain why that count is correct (the left half is sorted, so everything from i to mid exceeds a[j]), you have answered the question completely.

Interview Q&A
What is the maximum possible number of inversions?

N(N−1)/2, achieved by a strictly descending array. Note this exceeds a 32-bit int for N around 105 — use long long.

Why a[i] <= a[j] and not <?

Equal elements are not inversions (the definition requires strictly greater). Using < would count them, over-reporting on arrays with duplicates — and it also makes the sort unstable.

Any approach other than merge sort?

A Binary Indexed Tree (Fenwick): compress the values, then scan right to left querying how many smaller elements have already been seen. Also O(N log N), and it is the approach that generalises best to online/streaming variants.

What does the inversion count mean intuitively?

It is the minimum number of adjacent swaps needed to sort the array — exactly the number of swaps bubble sort would perform. That framing often unlocks the problem for the interviewer.

Reverse Pairs

LC 493Merge sortO(N log N)Hardest of the set

Count pairs (i, j) with i < j and arr[i] > 2 × arr[j]. Almost inversions — but the factor of 2 breaks the shortcut, so counting needs its own separate pass.

Input : arr = [40, 25, 19, 12, 9, 6, 2] Output: 15 Why a SEPARATE counting loop? In plain inversions, the merge comparison itself detects the pair. Here the condition is arr[i] > 2*arr[j], which is NOT the condition used to merge (arr[i] <= arr[j]). So you must count first, then merge.

Brute force

Two nested loops testing arr[i] > 2 × arr[j]. O(N²) — times out for N = 105.

Optimal — merge sort with a dedicated counting pass

  1. Recurse on both halves as in merge sort. Both halves are now sorted.
  2. Counting pass: walk i over the left half with a pointer j into the right half. For each i, advance j while arr[i] > 2 × arr[j], then add (j − (mid+1)) to the count.
  3. Because both halves are sorted, j never moves backwards — the whole counting pass is O(N), not O(N²).
  4. Then perform the ordinary merge.
reverse pairs
void mergeHalves(vector<int>& a, int low, int mid, int high) {
    vector<int> temp;
    int i = low, j = mid + 1;
    while (i <= mid && j <= high)
        temp.push_back(a[i] <= a[j] ? a[i++] : a[j++]);
    while (i <= mid)  temp.push_back(a[i++]);
    while (j <= high) temp.push_back(a[j++]);
    for (int k = low; k <= high; k++) a[k] = temp[k - low];
}

long long countPairs(vector<int>& a, int low, int mid, int high) {
    long long count = 0;
    int j = mid + 1;
    for (int i = low; i <= mid; i++) {              // j never goes backwards
        while (j <= high && (long long)a[i] > 2LL * a[j]) j++;
        count += (j - (mid + 1));
    }
    return count;
}

    count += reversePairsHelper(a, mid + 1, high);
    count += countPairs(a, low, mid, high);        // COUNT first...
    mergeHalves(a, low, mid, high);                // ...then merge
    return count;

def reverse_pairs(arr):
    a = list(arr)                                  # copy - keeps input intact

    def merge_halves(low, mid, high):
        temp, i, j = [], low, mid + 1
        while i <= mid and j <= high:
            if a[i] <= a[j]:
                temp.append(a[i]); i += 1
            else:
                temp.append(a[j]); j += 1
        while i <= mid:
            temp.append(a[i]); i += 1
        while j <= high:
            temp.append(a[j]); j += 1
        a[low:high + 1] = temp

    def count_pairs(low, mid, high):
        count, j = 0, mid + 1
        for i in range(low, mid + 1):              # j never goes backwards
            while j <= high and a[i] > 2 * a[j]:
                j += 1
            count += (j - (mid + 1))
        return count

    def helper(low, high):
        if low >= high:
            return 0
        mid = (low + high) // 2
        count = helper(low, mid) + helper(mid + 1, high)
        count += count_pairs(low, mid, high)       # COUNT first...
        merge_halves(low, mid, high)               # ...then merge
        return count

    return helper(0, len(a) - 1)

Two things that break this

1. Counting after merging destroys the left/right separation — you must count first. 2. 2 * a[j] overflows when a[j] is near INT_MAX; use 2LL * a[j] in C++. LeetCode 493's test suite contains exactly that case.

Interview Q&A
Why is the counting pass O(N) and not O(N²)?

Because j is declared outside the i loop and only ever increases. Across the entire pass it advances at most high − mid times, so the total work is linear — the same amortised two-pointer argument as sliding windows.

Why can't you count during the merge, like in C10?

In C10 the merge condition (a[i] > a[j]) is the inversion condition, so counting is free. Here the target condition (a[i] > 2·a[j]) differs from the merge condition, so the two pointer walks diverge and need separate passes.

Generalise to arr[i] > k × arr[j].

Change the constant — the algorithm is unchanged. Be careful with negative values and with k < 1, where the inequality direction and overflow behaviour need re-checking.

C12

Maximum Product Subarray

LC 152Prefix/suffix trickO(N) / O(1)Sign trap

Find the maximum product of any contiguous subarray. Sounds like Kadane — but sign flips make it genuinely different.

Input : arr = [2, 3, -2, 4] → Output: 6 ([2, 3]) Input : arr = [-2, 0, -1] → Output: 0 Input : arr = [-2, -3, -4] → Output: 12 ([-2, -3]) WHY KADANE FAILS DIRECTLY: A very negative running product is not a liability — one more negative number turns it into a huge positive. So you cannot "reset when negative" the way you do for sums.

Brute force / better

All subarrays with an inner product → O(N³); running product in the inner loop → O(N²).

Optimal 1 — prefix and suffix products (the intuitive one)

Insight: the answer's subarray must either start at index 0, end at index n−1, or be bounded by zeros. So scan a running product from the left and another from the right; reset either to 1 whenever it hits 0. The maximum value seen across both scans is the answer.

  1. pre = 1, suf = 1, ans = INT_MIN.
  2. For i from 0 to n−1: if pre == 0 set pre = 1; if suf == 0 set suf = 1.
  3. pre *= arr[i] and suf *= arr[n−1−i].
  4. ans = max(ans, max(pre, suf)).

Optimal 2 — track max and min together

Because a negative number swaps the roles of maximum and minimum, carry both. At each element, if the value is negative, swap them first, then apply the usual "extend or start fresh" rule.

max product subarray — both methods
// METHOD 1 - prefix & suffix products (easiest to explain)
long long maxProductPrefixSuffix(vector<int>& arr) {
    int n = arr.size();
    long long pre = 1, suf = 1, ans = LLONG_MIN;
    for (int i = 0; i < n; i++) {
        if (pre == 0) pre = 1;                  // a zero breaks the chain
        if (suf == 0) suf = 1;
        pre *= arr[i];                          // running from the LEFT
        suf *= arr[n - 1 - i];                  // running from the RIGHT
        ans = max(ans, max(pre, suf));
    }
    return ans;
}

// METHOD 2 - carry max AND min (a negative swaps their roles)
int maxProductMinMax(vector<int>& arr) {
    int maxP = arr[0], minP = arr[0], ans = arr[0];
    for (int i = 1; i < arr.size(); i++) {
        int v = arr[i];
        if (v < 0) swap(maxP, minP);            // negative flips the extremes
        maxP = max(v, maxP * v);                // extend, or start fresh at v
        minP = min(v, minP * v);
        ans  = max(ans, maxP);
    }
    return ans;
}

Time O(N)Space O(1)
The counting argument that makes method 1 obvious

If the number of negatives in a zero-free block is even, the whole block is the answer. If it is odd, you must drop everything up to and including either the first negative or the last negative — which is exactly what a left-scan and a right-scan cover between them. Zeros just restart both chains.

Interview Q&A
Why does plain Kadane fail here?

Kadane relies on "a negative running total can only hurt". For products that is false: a large negative product becomes a large positive one the moment another negative arrives. The monotonic reasoning that justifies the reset simply does not hold.

Why reset to 1 rather than 0 on a zero?

1 is the multiplicative identity — it starts a fresh product without contaminating it. Resetting to 0 would zero out everything afterwards. (Note the parallel: Kadane resets to 0, the additive identity.)

Handle an array that is a single element, like [-3]?

Both methods return −3 correctly, because ans is initialised to −∞ (method 1) or to arr[0] (method 2). Initialising ans = 0 would wrongly return 0 — the same trap as Kadane's.

Which method would you write in an interview?

Method 2 is shorter, but method 1 is far easier to justify out loud with the even/odd-negatives argument. Explain method 1's reasoning, then write whichever you code more reliably — and say why.

Rapid-fire questions they actually ask

Cover the answer, say yours out loud, then open it. If you can do all 25 without hesitating, the array round is yours.

Why is array access O(1)?

Elements are contiguous and equally sized, so the address is computed as base + i × size — arithmetic, not searching.

Subarray vs subsequence vs subset?

Subarray = contiguous (N(N+1)/2 of them). Subsequence = order preserved, gaps allowed (2N). Subset = any selection, order irrelevant (2N).

What does "amortised O(1)" mean for push_back?

Doubling makes reallocation rare: N pushes cost O(N) total because the copies form the geometric series 1+2+4+…+N ≈ 2N. Any single push can still be O(N).

When does a sliding window NOT work?

When the array contains negatives (or the condition is not monotonic as the window grows). Then use prefix sums with a hashmap instead.

Longest subarray vs count of subarrays — what changes in the code?

Longest stores the earliest index per prefix and never overwrites. Counting stores a frequency and always increments, seeded with {0:1}.

Why seed the prefix map with {0 : 1}?

It represents the empty prefix, so subarrays starting at index 0 are counted. Without it, [3] with k=3 returns 0.

State Kadane's algorithm in one sentence.

Carry a running sum, record the best sum seen, and reset the running sum to 0 whenever it goes negative — because a negative prefix can only hurt what follows.

Why does Kadane fail for products?

A very negative product is not a liability — one more negative flips it to a large positive. Monotonicity fails, so use prefix/suffix products or carry both max and min.

Why must Moore's voting be verified?

It guarantees only that if a majority exists, the survivor is it. On [1,2,3] it returns a non-majority element, so a counting pass is required unless existence is promised.

How many elements can appear more than N/3 times? More than N/K?

At most 2, and in general at most K−1 — otherwise the total count would exceed N. That is why the N/3 version needs exactly two counters.

Rotate an array left by d — the algorithm and the one line people forget?

Reverse [0,d−1], reverse [d,n−1], reverse the whole array. The forgotten line is d = d % n, without which d > n goes out of bounds.

Rotate a matrix 90° clockwise?

Transpose (swapping only the upper triangle, j starting at i+1), then reverse each row. Anticlockwise: transpose then reverse each column.

Why does Dutch flag not advance mid after swapping with high?

The value that arrives from the right end has never been examined. Skipping it leaves an unclassified element and breaks the invariant.

Next permutation in three words?

Pivot, swap, reverse. Find the rightmost i with a[i] < a[i+1], swap it with the smallest larger element to its right, reverse the suffix.

Why is Longest Consecutive Sequence O(N) despite a nested loop?

The inner walk only runs for values that start a run (those with no predecessor in the set), and each run is walked exactly once — so total inner work is O(N).

What is the worst case of an unordered_map solution?

O(N) per operation under adversarial collisions, so O(N²) overall. std::map gives a guaranteed O(log N) per operation, and a randomised custom hash defends the unordered version.

What is the maximum number of inversions in an array of size N?

N(N−1)/2, from a strictly descending array. It exceeds 32-bit range around N = 105, so use 64-bit counters.

Why can inversions be counted during the merge but reverse pairs cannot?

For inversions the merge comparison is the counting condition. For reverse pairs the condition (a[i] > 2·a[j]) differs from the merge condition, so a separate two-pointer counting pass is needed before merging.

When do you sort by start and when by end?

Sort by start to merge overlapping intervals. Sort by end to select the maximum number of non-overlapping intervals (activity selection).

Two ways to find a missing number, and which do you ship?

Sum formula (n(n+1)/2 − Σarr) and XOR. Ship XOR — it cannot overflow, whereas the sum for N=105 already exceeds a 32-bit int.

Explain x & (-x).

It isolates the lowest set bit, because -x in two's complement is ~x + 1, which flips everything above that bit and leaves it intact.

Which array problems need long long?

Kadane on large values, 4-sum (four values near 109), reverse pairs (2 × a[j]), inversion counts, the repeating-and-missing sum-of-squares, and any prefix sum over 105 large elements.

Given N = 10⁵, what complexity are you aiming for?

O(N log N) or better. O(N²) is 1010 operations and will time out. Saying this before coding earns credit and often earns a hint.

Why is for i: for j: mat[i][j] faster than the reverse, at the same complexity?

Row-major storage means the first order walks memory linearly and uses every fetched cache line fully; the second jumps by a row each step and thrashes the cache.

Name the three test cases you volunteer for every array problem.

Empty or single-element array; all negatives (or all identical); and a boundary case where the answer sits at the first or last index.

How to answer in the interview — the 5-step script

  1. Restate and clarify. "Sorted? Duplicates? Can values be negative? What are the constraints on N? Do you want indices or just the value? Is O(1) space required?" Each question maps directly to a fork in this notebook.
  2. State the brute force with its complexity. One sentence. It proves you understand the problem and gives you something to beat.
  3. Name the pattern out loud. "The values can be negative, so a sliding window is invalid — I will use prefix sums with a hashmap." That sentence is what is being graded.
  4. Write the code while narrating the invariant. Name your variables clearly and say what each one guarantees at every step.
  5. Dry run three cases unprompted: a normal one, the smallest input, and an adversarial one (all negative, all duplicates, answer at a boundary). Then restate the final time and space complexity.

Ten questions to ask before writing a single line

  1. Is the array sorted? (unlocks two pointers and binary search)
  2. Can values be negative? (decides window vs prefix map)
  3. Are there duplicates? (decides skip logic)
  4. What are the constraints on N and on the values? (decides the target complexity and whether you need 64-bit types)
  5. Can I modify the input array? (unlocks in-place tricks and index marking)
  6. Do you want indices, the values, or just a count?
  7. What should I return when no answer exists?
  8. Is O(1) extra space a requirement or a bonus?
  9. Is the array guaranteed non-empty?
  10. Will this be queried once, or many times? (decides whether preprocessing pays off)
