How JavaScript actually runs

What you'll own after thisA correct mental model of where your code executes, what the engine does with it, and why "JavaScript is single-threaded" is the sentence every interviewer starts from.

JavaScript is a language. It does not run by itself. It needs a host environment that provides an engine plus a set of extra objects.

Same language, different toolbox. document.getElementById crashes in Node. require('fs') crashes in a browser. Nothing about the language changed — only the host.

What the engine does to your file

  1. Parse — reads the text, builds an Abstract Syntax Tree. Syntax errors are thrown here, before a single line executes.
  2. Compile — V8 compiles to bytecode, then hot functions get optimised to machine code (JIT). JavaScript is not "interpreted line by line" any more; saying so in an interview dates you.
  3. Execute — runs inside an execution context, tracked on the call stack.

Because a syntax error is caught at parse time, this whole file does nothing at all:

console.log("does this print?");
const x = ;   // ← syntax error. Delete the ; to fix.

One stack, one thread

JavaScript has one call stack. One thing happens at a time. When a function is called it is pushed on; when it returns it is popped off.

function third()  { console.log("stack: main > first > second > third"); }
function second() { third(); }
function first()  { second(); }

first();
console.log("back to main, stack is empty again");

Blow the stack on purpose. This is the classic RangeError:

function forever(n) { return forever(n + 1); }
try { forever(0); }
catch (e) { console.log(e.name + ": " + e.message); }

Where to write code

Everything in this notebook runs in your browser's console too. Open DevTools with F12 → Console tab. For Node, install it, then node file.js. Two rules that will save you an hour:

  • console.log is your oscilloscope. Log early, log often, log the type as well as the value: console.log(typeof x, x).
  • Every file you write should start with "use strict" — or be an ES module, which is strict automatically. Strict mode turns silent failures into loud errors, which is what you want.

Interview bank · Chapter 00

Is JavaScript compiled or interpreted?

Neither label is fully accurate. Modern engines like V8 use just-in-time compilation: source is parsed into an AST, compiled to bytecode by an interpreter (Ignition), and functions that run frequently are re-compiled into optimised machine code by a compiler (TurboFan). If assumptions break — say a function that always received numbers suddenly receives a string — the code is deoptimised back to bytecode.

What does "JavaScript is single-threaded" mean, and how does it do two things at once?

It means there is one call stack, so exactly one piece of JavaScript executes at any instant. Concurrency comes from the host environment, not the language: timers, network requests and file I/O are handed off to the browser or to libuv in Node, which handle them on other threads. When they finish, a callback is placed on a queue and the event loop pushes it onto the stack once the stack is free.

Difference between the JavaScript engine and the runtime?

The engine (V8) implements the ECMAScript specification — syntax, types, objects, the heap, the call stack. The runtime is the engine plus everything the host adds: the event loop, the task queues, and host APIs such as the DOM or Node's fs. setTimeout is not part of the language spec; it is a runtime API.

What is ECMAScript? Is it the same as JavaScript?

ECMAScript is the standard (maintained as ECMA-262); JavaScript is the best-known implementation of it. Yearly editions since ES2015 (ES6) add features. In practice people say "ES6+" to mean let/const, arrow functions, classes, promises, modules, destructuring, and everything after.

Why is "use strict" recommended?

It removes silent failures: assigning to an undeclared variable throws instead of creating a global; duplicate parameter names throw; this inside a plain function call is undefined instead of the global object; writing to a read-only property throws. ES modules and class bodies are always strict.

Hoisting and the Temporal Dead Zone

Before running a scope, the engine scans it and registers every declaration. That registration step is hoisting. What differs is the initial state of the binding:

  • var → created and set to undefined. Reading it early gives undefined.
  • let/const → created but left uninitialised. Reading it before the declaration line throws. That window is the Temporal Dead Zone.
  • Function declarations → fully hoisted, body and all. You can call them before they appear.
console.log(hoistedVar);     // undefined — declared, not yet assigned
var hoistedVar = "assigned";

sayHi();                     // works — whole function is hoisted
function sayHi() { console.log("hi from a hoisted function"); }

The classic loop bug

This is asked in almost every fresher interview. Run it, then change var to let and run again.

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log("var i =", i), 10);
}
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log("let j =", j), 20);
}

var i is one single variable shared by all three callbacks; by the time they run, the loop has finished and i is 3. let j creates a fresh binding per iteration, so each callback captures its own copy. The pre-ES6 fix was an IIFE (Chapter 05).

Naming, in practice

  • camelCase for variables and functions, PascalCase for classes, UPPER_SNAKE for true constants.
  • Booleans read as questions: isActive, hasPermission, canEdit.
  • Default to const. Switch to let only when you actually reassign. Never write var.

Interview bank · Chapter 01

Explain var, let and const.

var is function-scoped, hoisted and initialised to undefined, and can be redeclared. let and const are block-scoped, hoisted into a Temporal Dead Zone so early access throws, and cannot be redeclared in the same scope. const additionally forbids reassignment of the binding — though objects it points at remain mutable.

What is the Temporal Dead Zone?

The region of a block from the start of the scope until the let/const declaration is evaluated. The binding exists but is uninitialised, so any read throws ReferenceError: Cannot access 'x' before initialization. It exists to make use-before-declare a loud error rather than a silent undefined.

Is hoisting real, or is that just a teaching metaphor?

Nothing physically moves. During the creation phase of an execution context the engine registers all declarations in the scope's environment record before executing any statements. "Hoisting" is the name for that pre-registration. The observable difference between var and let is only the initial value of the binding.

Does const make a value immutable?

No. It makes the binding immutable. const arr = [] then arr.push(1) is legal. For value immutability use Object.freeze, and remember it is shallow — nested objects need a recursive freeze or a library.

What is variable shadowing?

An inner scope declaring a variable with the same name as an outer one. The inner name wins inside that scope. Illegal shadowing is when a let in a block conflicts with a var of the same name that crosses the block boundary — that throws a SyntaxError.

Why does the setTimeout-in-a-for-loop question get asked so often?

Because answering it correctly requires three concepts at once: closures capture variables not values, var is function-scoped while let is per-iteration, and asynchronous callbacks run after the synchronous loop completes. It is a compact test of whether you understand the runtime.

Data types and the coercion minefield

What you'll own after thisThe seven primitives, why typeof null lies, truthy/falsy from memory, and a defensible answer to "== or ===?".

Two categories

Primitives are immutable and copied by value: string, number, boolean, null, undefined, symbol, bigint. Everything else — objects, arrays, functions, dates, maps — is an object, copied by reference.

// copied by VALUE
let a = 10;
let b = a;
b = 99;
console.log("primitive:", a, b);      // 10 99 — independent

// copied by REFERENCE
let o1 = { n: 10 };
let o2 = o1;
o2.n = 99;
console.log("object:", o1.n, o2.n);   // 99 99 — same object!
Why this matters for backend

Passing a request body object into a helper and mutating it there changes the caller's object too. Most "mystery state" bugs in Express handlers are this. Copy defensively: const safe = { ...body }.

== versus ===

=== compares type and value. == converts first, following a spec algorithm that nobody remembers correctly under pressure.

console.log(1 == "1");          // true  — string converted to number
console.log(0 == false);        // true
console.log(0 == "");           // true
console.log("" == false);       // true
console.log(null == 0);         // false — null only equals undefined
console.log([] == false);       // true  — [] → "" → 0
console.log([1] == 1);          // true  — [1] → "1" → 1

console.log("--- strict ---");
console.log(1 === "1", 0 === false, null === undefined);
The rule

Always use ===. The single accepted exception is x == null, which is a compact way of asking "is it null or undefined?". Say exactly that in an interview and you sound like someone who has read the spec rather than a blog post.

NaN, the value that isn't equal to itself

Interview bank · Chapter 02

List the primitive types.

string, number, boolean, null, undefined, symbol, bigint — seven. They are immutable and compared by value. Everything else is an object compared by reference.

Why is typeof null "object"?

In the original implementation values were stored with a type tag in the low bits; the object tag was 000 and the null pointer was all zeros, so null read as an object. Fixing it would break existing sites, so it was standardised as-is.

== vs === — and when would you ever use ==?

=== is strict: same type and same value. == applies type coercion first. Use === everywhere except the idiom x == null, which tests for null or undefined in one comparison.

Name all falsy values.

false, 0, -0, 0n, "", null, undefined, NaN. Notably [] and {} are truthy, which is why if (arr) never tells you whether an array has items — check arr.length.

Why does 0.1 + 0.2 !== 0.3?

Numbers are IEEE-754 64-bit binary floats. 0.1 and 0.2 have no exact binary representation, so their stored values are slightly off and the sum lands on 0.30000000000000004. Compare with a tolerance (Number.EPSILON) or work in integers.

Difference between null and undefined in a REST response?

undefined is dropped by JSON.stringify, so the key disappears from the payload entirely; null survives as an explicit null. That distinction matters in PATCH semantics: a missing key usually means "don't change this", while null means "clear this field".

How do you reliably check if a value is an array?

Array.isArray(x). typeof returns "object", and instanceof Array fails across realms (iframes, Node vm contexts) because each realm has its own Array constructor.

Short-circuiting

&& returns the first falsy operand or the last one. || returns the first truthy operand or the last one. They return values, not booleans — that's what makes them useful.

console.log("a" && "b");        // "b"
console.log(0 && "b");          // 0    — stops early
console.log("" || "default");   // "default"
console.log("Alan" || "guest"); // "Alan"

// guard pattern: right side only runs if left is truthy
const user = { profile: { city: "Kottayam" } };
user.profile && console.log("city:", user.profile.city);
The || default bug

|| falls back on any falsy value, so a legitimate 0 or "" gets replaced. Use ?? (nullish coalescing), which only falls back on null or undefined.

function makeConfig(opts) {
  return {
    retriesBAD:  opts.retries || 3,   // 0 becomes 3 — wrong!
    retriesGOOD: opts.retries ?? 3,   // 0 stays 0
    nameBAD:     opts.name || "anon",
    nameGOOD:    opts.name ?? "anon"
  };
}
console.log(makeConfig({ retries: 0, name: "" }));

Optional chaining

const res = { data: { items: [{ id: 1 }] } };
const empty = {};

console.log(res.data?.items?.[0]?.id);       // 1
console.log(empty.data?.items?.[0]?.id);     // undefined — no crash
console.log(empty.doStuff?.());              // undefined — safe call

try { console.log(empty.data.items); }
catch (e) { console.log("without ?. →", e.name); }

// combine with ?? for a clean default

Branching

const status = 404;

if (status >= 500)      console.log("server error");
else if (status >= 400) console.log("client error");
else if (status >= 300) console.log("redirect");

function resolve(userOpts = {}) {

Interview bank · Chapter 03

What does the && operator actually return?

Not a boolean — it returns the first falsy operand, or the last operand if all are truthy. || mirrors it: first truthy operand, else the last. Both short-circuit, meaning the right side is never evaluated when the result is already determined.

Difference between || and ??

|| falls back when the left side is any falsy value; ?? falls back only for null and undefined. For default values where 0, "" or false are legitimate inputs, ?? is correct and || is a bug.

What is optional chaining and what does it protect against?

?. short-circuits to undefined if the value to its left is null or undefined, instead of throwing TypeError: Cannot read properties of undefined. It works for properties (a?.b), indexes (a?.[0]) and calls (fn?.()). Don't use it to paper over data you should have validated.

Why must switch cases have break?

Without break, execution falls through into the following cases. That is occasionally intentional — stacking case 401: case 403: to share a body — but usually a bug. switch matches with strict equality, so case "1" will not match the number 1.

Difference between i++ and ++i?

Both increment. i++ evaluates to the value before incrementing; ++i evaluates to the value after. It only matters when you use the expression's result, e.g. arr[i++].

function primesUpTo(n) {

  isPrime[0] = isPrime[1] = false;

for...in vs for...of

for...in iterates enumerable string-keyed properties, including inherited ones — meant for objects. for...of iterates values of anything implementing the iterable protocol: arrays, strings, Maps, Sets, generators, NodeLists. On an array, for...in gives string indices and can pick up extra properties.

No. forEach always visits every element; return only skips the current callback. Use for...of with break, or some/every (which short-circuit), or find/findIndex when you want the matching element.

Which loop is fastest?

A plain indexed for loop is usually marginally fastest because it avoids a function call per element, but on modern engines the difference is negligible for anything under millions of iterations. Choose for readability first; optimise only with a measurement in hand.

An object is iterable if it has a [Symbol.iterator] method returning an iterator — an object with a next() that returns { value, done }. That single protocol powers for...of, spread, destructuring and Array.from. You can make your own class iterable by implementing it.

Function declaration vs function expression

A declaration is hoisted with its body, so it can be called before it appears in the source. An expression is assigned to a variable — the variable is hoisted (as undefined for var, in the TDZ for let/const) but the function value is not available until that line runs.

What is a first-class function?

A function treated like any other value: it can be assigned to variables, stored in arrays or objects, passed as an argument, and returned from another function. JavaScript has first-class functions, which is what makes higher-order functions and callbacks possible.

What is a higher-order function? Give three you use daily.

A function that takes a function as an argument, returns a function, or both. Daily examples: array.map, array.filter, setTimeout, addEventListener, and Express middleware — app.use(fn) is a higher-order call.

What is an IIFE and why was it used?

An Immediately Invoked Function Expression: (function(){ ... })(). Before block scoping and modules existed, it was the only way to create a private scope and avoid polluting the global namespace — the module pattern was built on it. Modern code uses let/const and ES modules instead, but you will still see IIFEs in older bundles and for top-level await workarounds.

What is a pure function?

One whose return value depends only on its arguments and which causes no observable side effects — no mutation of inputs, no I/O, no reliance on external mutable state. Pure functions are deterministic, so they are easy to unit test and safe to memoise.

Difference between parameters and arguments?

Parameters are the names in the function definition; arguments are the actual values passed at the call site. Rest parameters (...args) collect extra arguments into an array in the definition; the spread operator expands an iterable into arguments at the call site.

Why can't an arrow function be used as a constructor?

Arrow functions have no [[Construct]] internal method, no prototype property, and no own this binding — new has nothing to bind to, so it throws TypeError: X is not a constructor.

Interview bank · Chapter 06

Define a closure in one sentence.

A closure is a function together with a reference to the lexical environment in which it was created, letting it access those outer variables even after the outer function has returned.

Give a practical use of closures.

Data privacy (module pattern), function factories such as a configured logger, memoisation caches, once guards for one-time initialisation, debounce and throttle wrappers, and partial application/currying. In React, every hook's state persists via closures.

Do closures cause memory leaks?

Not inherently — they keep captured variables reachable, which is the point. A leak happens when a long-lived closure captures something large that is no longer needed: uncleared intervals, un-removed event listeners, or unbounded caches. The fix is lifecycle management, not avoiding closures.

What is the difference between scope and a closure?

Scope is a compile-time concept — the region where a name is visible, determined lexically by where you wrote the code. A closure is the runtime consequence: a function object retaining its defining scope after that scope's execution has ended.

What is currying and why is it useful?

Transforming a function of N arguments into a chain of N single-argument functions. It enables partial application — pre-filling arguments to build specialised functions, e.g. const logError = log("ERROR") — and makes functions easier to compose in pipelines.

Explain the output of a loop that pushes closures.

With var, all closures capture the one function-scoped variable, so after the loop they all read its final value. With let, the specification creates a fresh binding per iteration and copies the value forward, so each closure captures a distinct variable and sees its own value.

Both convert an iterable into an array. Array.from additionally works on array-like objects that are not iterable (having length and index keys, like arguments or an old NodeList), and accepts a mapping function as a second argument — Array.from({length: 3}, (_, i) => i).

Interview bank · Chapter 08

Dot notation vs bracket notation?

Dot notation needs a valid identifier known at write time. Bracket notation accepts any expression, so it is required for keys with spaces or hyphens, keys that start with a digit, and keys held in a variable — which is what makes dynamic lookups like obj[field] possible.

How do you copy an object, and what are the pitfalls?

{...obj} and Object.assign({}, obj) are shallow — nested objects stay shared. JSON.parse(JSON.stringify(obj)) is deep but silently drops functions, undefined and symbols, turns Date into a string, and throws on circular references. structuredClone is the modern answer: deep, handles Date, Map, Set and cycles, but still cannot clone functions.

Object.freeze vs const?

const prevents rebinding the variable; Object.freeze prevents adding, deleting or changing the object's own properties. Freeze is shallow — nested objects remain mutable — and in sloppy mode a write fails silently rather than throwing.

Difference between "in" and hasOwnProperty?

in returns true for inherited properties too; hasOwnProperty (or the safer Object.hasOwn) only checks own properties. Object.hasOwn is preferred because it still works on objects created with Object.create(null), which have no prototype and therefore no hasOwnProperty method.

What does JSON.stringify do with undefined and functions?

In an object, keys whose values are undefined, functions or symbols are omitted entirely. In an array, those same values become null to preserve indices. Date objects are serialised via toJSON() to an ISO string, and circular structures throw a TypeError.

How would you compare two objects for equality?

=== only compares references. For a shallow comparison, check that both have the same key count and every key's values are strictly equal. For deep equality you recurse, handling arrays, Dates and null explicitly — or use a tested library. Note that key order does not matter for equality, but does for JSON.stringify comparison, which is why stringify-and-compare is unreliable.

function isAnagram(a, b) {

  for (const ch of b) {
    if (!count.has(ch)) return false;
    const left = count.get(ch) - 1;
    left === 0 ? count.delete(ch) : count.set(ch, left);

How is the value of `this` determined?

By the call site, in this precedence: new binding, then explicit binding via call/apply/bind, then implicit binding via a method call on an object, then the default binding (undefined in strict mode, global object otherwise). Arrow functions have no own binding and resolve this lexically from the enclosing scope.

call vs apply vs bind

All three set this. call invokes immediately with comma-separated arguments; apply invokes immediately with an array of arguments; bind does not invoke — it returns a new function permanently bound to that this, optionally with preset leading arguments (partial application).

Why does `this` break in a callback, and what are the fixes?

Passing obj.method as a value drops the receiver, so at call time there is no object to the left of a dot. Fixes: pass an arrow that closes over this, use .bind(this), use the thisArg parameter that array methods accept, or define the method as a class field with an arrow function.

What is `this` at the top level?

In a browser script it is window. In a CommonJS module in Node it is module.exports (an empty object). In an ES module it is undefined. globalThis is the portable way to reach the global object everywhere.

Can you bind an arrow function?

You can call .bind() on it, but it has no effect on this — arrows capture this lexically at creation and it can never be changed. Arguments can still be partially applied.

Explain prototypal inheritance.

Objects link to other objects through an internal [[Prototype]]. Property lookup walks that chain until the property is found or the chain ends at null. There are no classes at runtime — class is syntax over constructor functions and prototype objects.

Are JavaScript classes "just syntactic sugar"?

Mostly, but not entirely. Classes add real semantics: the body is always strict, methods are non-enumerable, calling a class without new throws, super and private # fields have no plain-function equivalent, and class declarations are in the TDZ rather than hoisted like functions.

Difference between __proto__ and prototype?

prototype is a property on constructor functions — the object that will become the prototype of instances they create. __proto__ (properly Object.getPrototypeOf) is the actual link on any object to its prototype. So dog.__proto__ === Dog.prototype.

What happens when you call a function with new?

A new empty object is created, its prototype is set to the function's prototype property, the function runs with this bound to that object, and the object is returned automatically — unless the function explicitly returns some other object, in which case that wins.

How do you achieve encapsulation?

Private class fields with # are enforced by the engine and are the modern answer. Before them, the options were closures via the module pattern, WeakMap keyed by instance, or the underscore naming convention — which is documentation, not protection.

What is method shadowing and how do you call the parent version?

Defining a method on a subclass with the same name hides the parent's. super.method() invokes the parent implementation, which is how you extend behaviour rather than replace it. In a subclass constructor, super() must be called before touching this.

Composition vs inheritance — which do you prefer?

Composition, by default. Deep inheritance chains couple classes tightly and break when a subclass needs only part of the parent. Composing small focused objects or functions — passing a logger and a repository into a service rather than extending a base class — keeps units testable and swappable. Inheritance is a good fit for genuine "is-a" hierarchies such as error types.

Explain try/catch/finally.

try holds code that may throw; catch receives the thrown value; finally runs regardless of whether an error occurred or a return executed — used for cleanup such as releasing a database connection. A return inside finally overrides one in try, which is a subtle trap.

Why throw Error objects instead of strings?

Error instances capture a stack trace, have a name and message, work with instanceof checks, and can be extended to carry domain fields such as an HTTP status. A thrown string gives you none of that.

Does try/catch catch asynchronous errors?

Only if the async operation is awaited inside the try. A rejection from a bare promise or an exception thrown inside a setTimeout callback happens on a later tick when that try block is long gone — use .catch() on the promise, or await it inside the try.

How do you handle errors globally in Node?

process.on('uncaughtException') and process.on('unhandledRejection') — but treat them as last-resort logging hooks, not recovery. The recommended practice is to log, flush, and exit, because the process is in an unknown state. In Express, a four-argument middleware (err, req, res, next) is the real error boundary.

What is error chaining / the cause option?

new Error("high level", { cause: originalError }) attaches the underlying error, so you can present a friendly message at the boundary while preserving the root cause for logs. Without it, wrapping an error destroys the diagnostic information.

The event loop

One call stack. When you call setTimeout or start a network request, the host takes over. When it finishes, the callback goes into a queue. The event loop's job is simple:

  1. Run the current synchronous code until the call stack is empty.
  2. Drain the entire microtask queue (promise callbacks, queueMicrotask, process.nextTick).
  3. Take one task from the macrotask queue (timers, I/O callbacks, events) and run it.
  4. Drain microtasks again. Repeat.

Microtasks always beat macrotasks. That single rule answers most output-order questions.

Interview bank · Chapter 13

Explain the event loop.

The runtime runs synchronous code to completion on the single call stack. Async operations are delegated to the host, and their callbacks are queued. When the stack empties, the loop drains the entire microtask queue, then takes one macrotask, then drains microtasks again. Promise callbacks are microtasks; timers and I/O callbacks are macrotasks, so a resolved promise's .then always runs before a setTimeout(…, 0) queued at the same moment.

Microtask vs macrotask?

Microtasks — promise reactions, queueMicrotask, MutationObserver, and process.nextTick in Node — run to exhaustion after each task, before rendering or the next macrotask. Macrotasks — setTimeout, setInterval, setImmediate, I/O and UI events — are taken one per loop iteration. An infinite chain of microtasks starves the loop entirely.

What are the three promise states?

Pending, fulfilled, and rejected. A promise settles once and is then immutable. .then attaches handlers that always run asynchronously as microtasks, even if the promise is already settled.

Promise.all vs allSettled vs race vs any

all waits for every promise but rejects immediately if one fails. allSettled waits for all and never rejects, giving an array of {status, value|reason}. race settles with the first promise to settle, whether it fulfils or rejects. any settles with the first to fulfil, rejecting with an AggregateError only if all reject.

Does await block the thread?

No. It suspends only the enclosing async function, returning control to the event loop; the rest of the program continues. The function resumes as a microtask when the awaited promise settles. It "blocks" logically within that function, not physically on the thread.

How do you run async work in parallel?

Start the operations first, then await the collection: const [a, b] = await Promise.all([f1(), f2()]). Awaiting each call on its own line serialises them. Inside a loop, use Promise.all(items.map(fn)) for independent work, and for...of with await only when order matters or you need to rate-limit.

Why doesn't forEach work with async/await?

forEach ignores the return value of its callback, so the promises the async callbacks return are discarded and never awaited. The loop finishes immediately. Use for...of to await sequentially, or Promise.all(arr.map(...)) to await in parallel.

What is an unhandled promise rejection?

A rejected promise with no rejection handler attached. In modern Node this terminates the process by default. Every promise chain needs a terminal .catch(), or the await needs to be inside a try/catch — and in Express, async handler errors must be forwarded with next(err) or wrapped, since Express 4 does not catch them for you.

Callback hell — what is it and how do promises solve it?

Deeply nested callbacks for sequential async steps, each with its own error branch, producing code that grows rightwards and duplicates error handling. Promises flatten this into a linear chain with a single .catch, and async/await makes it read like synchronous code with ordinary try/catch.

Difference between import and require?

import is ESM: static, hoisted, analysed at parse time, asynchronous, and supports tree-shaking and live bindings. require is CommonJS: a synchronous function call executed at runtime, so it can be conditional, and it returns a copy of module.exports at that moment.

Default export vs named exports — which is better?

Named exports are usually preferable: they are explicit, refactor-safe, autocompletable, and tree-shakeable. A default export can be renamed arbitrarily at every import site, which hurts searchability. Use a default when a module genuinely exports one thing, like a React component or an Express router.

What is dynamic import?

import("./mod.js") returns a promise resolving to the module namespace. It enables code splitting and lazy loading — loading an admin panel only for admins, or a heavy PDF library only when export is clicked — and it is the only way to conditionally import in ESM.

How do you avoid circular dependency problems?

Both systems tolerate cycles but give you partially initialised modules — in CJS you get an incomplete exports object, in ESM a TDZ error for const bindings. Fix the design: extract shared code into a third module, depend on interfaces rather than concrete modules, or move the import inside the function that needs it.

    throw err;

  }
}

What does REST mean in practice?

Resources identified by URLs, manipulated with standard HTTP methods, using standard status codes, with stateless requests — each request carries everything needed to process it, so no server-side session affinity is required. Nouns in paths (/users/1/orders), verbs in the method, not the URL.

PUT vs PATCH?

PUT replaces the entire resource — omitted fields should be cleared — and is idempotent. PATCH applies a partial update, sending only the fields that change. Idempotency matters because clients and proxies may safely retry a PUT, but not necessarily a PATCH or POST.

Why doesn't fetch throw on a 404?

Because the HTTP transaction succeeded — the server answered. The promise rejects only for network failures, DNS problems, CORS blocks, or an aborted request. Check response.ok (true for 200–299) and throw yourself.

What is CORS?

Cross-Origin Resource Sharing. Browsers enforce the same-origin policy, so a page on one origin cannot read a response from another unless the server sends permitting headers such as Access-Control-Allow-Origin. For non-simple requests the browser first sends an OPTIONS preflight. It is a browser restriction — server-to-server calls are unaffected, which is why the same request works in Postman but fails in the browser.

How do you cancel an in-flight request?

Create an AbortController, pass controller.signal to fetch, and call controller.abort(). The fetch promise rejects with an AbortError. It is the standard way to implement request timeouts and to cancel a stale search-as-you-type request.

What is the difference between authentication and authorisation?

Authentication establishes identity — logging in, verifying a token signature. Authorisation decides what that identity may do — role and permission checks. In an Express app they are usually two separate middlewares in that order, and they map to 401 and 403 respectively.

How does Node handle concurrency if JavaScript is single-threaded?

Your JavaScript runs on one thread, but Node delegates I/O to libuv, which uses the operating system's asynchronous facilities plus a thread pool (default size 4) for things like file system operations, DNS and crypto. Completed operations queue callbacks that the event loop runs on the main thread. CPU-bound work still blocks — that is what worker_threads or a separate process is for.

What are the phases of the Node event loop?

Timers (expired setTimeout/setInterval), pending callbacks, poll (retrieve new I/O events and run their callbacks), check (setImmediate), and close callbacks. Between phases Node drains process.nextTick and the promise microtask queue, with nextTick taking priority.

setImmediate vs setTimeout(fn, 0) vs process.nextTick?

process.nextTick runs before the event loop continues, ahead of promises — easy to starve the loop with. setTimeout(fn, 0) runs in the timers phase; setImmediate runs in the check phase. Inside an I/O callback, setImmediate always fires before a zero timer; at the top level the order between those two is not deterministic.

Why use streams?

Constant memory usage and lower time-to-first-byte. Reading a 2 GB file with readFile allocates 2 GB; a stream processes it in 64 KB chunks. Streams also compose through pipeline, which handles backpressure and cleans up on error — the reason to prefer it over chained .pipe() calls.

How do you keep secrets out of your code?

Read them from environment variables at startup, validate that they exist, and keep .env out of version control. In production the values come from the platform's secret manager rather than a file. Never log them, and never send them to the client — anything in a frontend bundle is public.

What is package.json, and what is the difference between dependencies and devDependencies?

The project manifest: name, entry point, scripts, module type and dependency ranges. dependencies are needed at runtime in production; devDependencies are build and test tools that are not installed with npm ci --omit=dev. package-lock.json pins the exact resolved tree so installs are reproducible — commit it.

function rateLimit({ windowMs = 1000, max = 3 } = {}) {
  const hits = new Map();                       // ip → { count, resetAt }

  return function (req, res, next) {
    const now = Date.now();
    const key = req.ip;
    let entry = hits.get(key);

    if (!entry || now > entry.resetAt) {
      entry = { count: 0, resetAt: now + windowMs };
      hits.set(key, entry);
    }
    entry.count++;

    if (entry.count > max) {
      const retryAfter = Math.ceil((entry.resetAt - now) / 1000);
      return res.set("Retry-After", retryAfter)
                .status(429)
                .json({ error: "TOO_MANY_REQUESTS", retryAfter });
    }
    next();
  };
}

What is middleware in Express?

A function with access to the request, the response and the next function, executed in registration order. It can modify the request, short-circuit by sending a response, or pass control onward. Everything in Express — body parsing, authentication, logging, routing, error handling — is middleware.

Walk me through the request lifecycle.

The HTTP server receives the request and hands it to the Express app. Application-level middleware runs in order — logging, CORS, body parsing, authentication. Express then matches the method and path against the router stack and runs the matching route's handlers. The handler calls the service layer, which calls the repository, and the result is serialised with res.json. If any middleware calls next(err), Express skips to the error-handling middleware. If nothing matched, the 404 handler responds.

How do you handle errors thrown inside async route handlers?

In Express 4 they are not caught automatically — an unhandled rejection leaves the request hanging. Either wrap the body in try/catch and call next(err), or wrap every handler in a helper that does Promise.resolve(fn(req,res,next)).catch(next). Then a single four-argument error middleware, registered last, formats the response. Express 5 forwards rejections automatically.

How does Express know a middleware is an error handler?

By its arity: a function declared with four parameters (err, req, res, next) is treated as an error handler and is skipped in the normal flow. That is why you cannot omit the unused next parameter.

How do you structure a Node backend project?

In layers by responsibility: routes handle HTTP shape, controllers orchestrate, services hold business rules, repositories hold data access, with middleware, config and utils alongside. The key discipline is keeping req and res out of services, which makes the business logic unit-testable and reusable from non-HTTP entry points such as cron jobs or queue consumers.

How do you validate incoming request data?

With a schema validation library — Zod, Joi or express-validator — applied as middleware before the handler, so a request either reaches the controller already valid or is rejected with a 400/422 listing every problem. Validate at the boundary, once, rather than sprinkling checks through the service.

What security basics would you add to an Express API?

helmet for security headers, a configured CORS allowlist rather than *, rate limiting on authentication routes, a body size limit, parameterised database queries to prevent injection, bcrypt or argon2 for password hashing, JWTs or httpOnly cookies for sessions, secrets from environment variables, and dependency auditing. Also: never echo internal error details to the client.

function debounce(fn, wait = 100) {          // run once, after the calls STOP
  let t;
  return (...args) => { clearTimeout(t); t = setTimeout(() => fn(...args), wait); };
}

function throttle(fn, interval = 100) {      // run at most once per interval
  let last = 0, timer;
  return (...args) => {
    const now = Date.now();
    if (now - last >= interval) { last = now; fn(...args); }
    else {                                   // trailing call so the last input isn't lost
      clearTimeout(timer);
      timer = setTimeout(() => { last = Date.now(); fn(...args); }, interval - (now - last));
    }
  };
}

Offset vs cursor pagination?

Offset (LIMIT/OFFSET) is simple and allows jumping to any page, but the database must scan and discard all skipped rows, so deep pages get slow — and rows inserted during browsing cause duplicates or skips. Cursor (keyset) pagination filters on the last seen sorted key, giving stable results and constant performance, at the cost of only supporting next/previous.

What is idempotency and where does it matter?

An operation is idempotent if performing it repeatedly has the same effect as performing it once. It matters wherever clients retry — payments, order creation, webhooks. The usual implementation is an Idempotency-Key header stored with the first response, so a replay returns the original result instead of creating a second charge.

Debounce vs throttle?

Debounce delays execution until a quiet period has passed — good for search-as-you-type and autosave, because only the final state matters. Throttle guarantees a maximum call rate — good for scroll, resize and mousemove, where you want regular updates during continuous activity.

Where would you add caching, and what's the risk?

On expensive reads that tolerate slight staleness: reference data, computed aggregates, third-party API responses. The risks are stale data and invalidation complexity — so define a TTL, invalidate explicitly on writes, and never cache per-user data under a shared key. Also watch for cache stampedes, where many requests miss simultaneously and all hit the database.

How do you prevent SQL injection?

Never build queries by string concatenation. Use parameterised queries or prepared statements so user input is always sent as data, never as SQL. ORMs and query builders do this by default. Additionally, allowlist any field that reaches the query structurally — column names for sorting cannot be parameterised, so they must be validated against a fixed set.

What is event bubbling and event delegation?

Bubbling is the propagation of an event from the target up through its ancestors. Delegation attaches a single listener on a common ancestor and identifies the real target with event.target.closest(selector). It reduces memory, keeps the code in one place, and automatically handles dynamically added elements.

event.target vs event.currentTarget?

target is the element the event actually originated on; currentTarget is the element whose listener is currently running. In delegation they differ — that difference is the whole mechanism.

innerHTML vs textContent vs innerText?

textContent gets or sets raw text including hidden elements and does not parse HTML — the safe default. innerHTML parses markup, so it is powerful and an XSS vector. innerText is layout-aware, respects CSS visibility, and forces a reflow when read, making it slower.

localStorage vs sessionStorage vs cookies?

localStorage persists until cleared and is shared across tabs of the same origin. sessionStorage is per-tab and cleared on close. Cookies are smaller, sent with every matching request automatically, and can be marked httpOnly and Secure — which is why session tokens belong in httpOnly cookies rather than localStorage, where any injected script can read them.

What causes a reflow, and how do you minimise it?

Reading a layout property such as offsetHeight after a style write forces the browser to recalculate layout synchronously. Batch reads together and writes together, use a DocumentFragment for bulk insertion, and prefer transform and opacity for animation since they can be composited without triggering layout.

// max sum of any k consecutive elements — O(n) instead of O(n·k)
function maxWindowSum(arr, k) {
  if (arr.length < k) return null;
  let sum = 0;
  for (let i = 0; i < k; i++) sum += arr[i];
  let best = sum;
  for (let i = k; i < arr.length; i++) {
    sum += arr[i] - arr[i - k];              // add one, drop one
    best = Math.max(best, sum);
  }
  return best;
}

function binarySearch(sorted, target) {
  let lo = 0, hi = sorted.length - 1;
  while (lo <= hi) {
    const mid = lo + ((hi - lo) >> 1);              // avoids overflow, integer divide
    if (sorted[mid] === target) return mid;
    sorted[mid] < target ? (lo = mid + 1) : (hi = mid - 1);
  }
  return -1;
}

function oneEdit(a, b) {

Map vs plain object — when do you choose which?

Use a Map when keys are not strings, when you add and delete frequently, when you need the size or guaranteed insertion order, or when keys could collide with prototype names. Use a plain object for fixed-shape records, for anything you will serialise to JSON, and when you want destructuring.

What are WeakMap and WeakSet for?

They hold keys weakly, so an entry does not prevent its key object from being garbage collected. That makes them right for attaching private metadata to objects you do not own, or caching per-object data, without creating a leak. They are not iterable and have no size, precisely because entries can vanish.

How would you find duplicates in an array efficiently?

One pass with a Set: for each element, if the Set already has it record it as a duplicate, otherwise add it. O(n) time and O(n) space, versus O(n²) for nested indexOf scanning. If the input is already sorted, comparing adjacent elements gives O(1) extra space.

Explain the sliding window technique.

Maintain a contiguous range with running state, and move its edges instead of recomputing from scratch. Adding the entering element and removing the leaving one makes each step O(1), so a problem that looks O(n·k) becomes O(n). It applies to fixed-size windows (max sum of k elements) and variable ones (longest substring under a constraint).

Why is shift() slower than pop()?

pop removes the last element in constant time. shift removes the first, which requires reindexing every remaining element — O(n). Building a queue with push/shift on a large array is a common accidental O(n²); use two pointers over the array or a linked structure instead.

What is a generator and when is it useful?

A function declared with function* that can pause at each yield and resume later, producing values lazily. Useful for infinite or very large sequences, custom iterators, streaming pagination, and cooperative control flow — the pattern Redux-Saga and older coroutine libraries were built on.

What problem do Symbols solve?

Guaranteed-unique property keys that never collide with string keys and are skipped by Object.keys and JSON.stringify. Well-known symbols such as Symbol.iterator and Symbol.toPrimitive let your objects hook into language-level behaviour.

What is the difference between ||= and ??=

||= assigns when the current value is falsy; ??= assigns only when it is null or undefined. Same distinction as || versus ??, and the same trap: ||= will overwrite a deliberate 0 or "".

Which ES2023 array methods would you reach for and why?

toSorted, toReversed, toSpliced and with — non-mutating counterparts of the classic methods. They remove the [...arr].sort() defensive-copy dance and make immutable state updates cleaner, which matters in React reducers and anywhere shared data is involved.

== coerces types before comparing; === requires the same type and value. Use ===, except x == null.

5. How is `this` determined?

By the call site: new > explicit bind/call/apply > method call on an object > default. Arrow functions inherit it lexically instead.

6. What does async/await return?

An async function always returns a promise; await unwraps a promise's fulfilment value and throws its rejection reason.

7. call vs apply vs bind?

Invoke with listed arguments; invoke with an array of arguments; return a new permanently bound function without invoking.

8. What is prototypal inheritance?

Property lookup walks a chain of linked objects until it finds the key or hits null. Classes are syntax over this.

9. map vs filter vs reduce?

Transform each element; keep the ones that pass a test; fold everything into a single value.

10. Shallow vs deep copy?

Shallow copies the top level and shares nested references; deep recursively duplicates everything. structuredClone is the built-in deep copy.

11. What is the TDZ?

The span from the start of a block to a let/const declaration, during which reading the binding throws a ReferenceError.

12. Why is typeof NaN "number"?

NaN is a value in the IEEE-754 double specification — a number that represents an invalid numeric result. Test it with Number.isNaN.

13. What is currying?

Turning an N-argument function into a chain of single-argument functions, which enables partial application.

14. What is debouncing?

Delaying execution until a burst of calls stops — useful when only the final state matters, like search-as-you-type.

15. Promise.all vs Promise.allSettled?

all rejects as soon as one promise rejects; allSettled waits for every promise and reports each outcome, never rejecting.

16. What is CORS?

A browser mechanism where a server must explicitly permit cross-origin reads through response headers; unrelated to server-to-server calls.

17. What is middleware?

A function with access to request, response and next, run in order, that can modify, short-circuit, or pass along the request.

18. PUT vs PATCH?

Full replacement versus partial update. PUT is idempotent by definition.

19. 401 vs 403?

Not authenticated versus authenticated but not permitted.

20. How do you store passwords?

Hashed with a slow, salted algorithm — bcrypt or argon2 — never encrypted and never plain. Compare with the library's timing-safe verify function.

21. What is a JWT?

A signed, base64url-encoded token of header, payload and signature. It is signed, not encrypted, so the payload is readable — never put secrets in it. The server verifies the signature instead of storing session state.

22. Why not use readFileSync in a server?

It blocks the single thread, so every concurrent request stalls until the file is read.

23. What does Object.freeze do?

Prevents adding, removing or changing an object's own properties — shallowly.

24. How do you avoid callback hell?

Promises flatten nesting into a chain with one .catch; async/await makes it read linearly with ordinary try/catch.

25. What is event delegation?

One listener on a shared ancestor identifying the real target via closest(), so dynamically added children are handled for free.

26. Difference between null and undefined?

undefined means never assigned, set by the engine; null is an explicit empty value set by the programmer.

27. What are ES modules?

The standard module system using static import/export, enabling tree-shaking, live bindings and top-level await.

28. What is the spread operator used for?

Expanding an iterable into elements or arguments, and shallow-copying or merging arrays and objects.

29. Why should services not receive req and res?

Coupling business logic to HTTP makes it untestable without a server and unusable from a CLI or a queue worker.

30. What does N+1 query mean?

Fetching a list with one query and then issuing a separate query per row. Fix it with a join, or by batching the ids into a single WHERE id IN (…) query.
